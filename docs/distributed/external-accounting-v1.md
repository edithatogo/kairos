# ADR: External accounting v1 — Track 48/49

Status: joint review draft. This is a proposed implementation contract, not an implemented API or accepted production-dispatch packet. Native baseline is normal merge `55fd635095483ada776ab1e1264b901991853f03`; preparation commit is `ffb788b`. The renewed initial-phase authority is recorded in the Track 29 renewal ADR. Existing native capabilities remain process-local. Source, manifests, locks, global status and the parent pin are outside this design leaf.

## 1. Ownership and runtime boundary

Introduce a separate `ExternalOptimisticRuntime<P, C>` where `P: OptimisticProcess` and `C: PortableModelCodec<P>`. Do not toggle a running native runtime into external mode or serialize native witnesses. It owns the engine, a fixed concrete `ExternalAccountingDriver`, and a model codec. The codec defines `encode_process(&P) -> Result<Vec<u8>, CodecError>`, `decode_process(&[u8]) -> Result<P, CodecError>`, `encode_snapshot(&P::Snapshot) -> Result<Vec<u8>, CodecError>` and `decode_snapshot(&[u8]) -> Result<P::Snapshot, CodecError>`, each binding model/schema/RNG versions and immutable length limits. It exports/imports bounded complete process and historical snapshot data only; it cannot mint accounting proofs, implement verification or commit journal transactions. The driver owns the audited canonical decoder, signature verifier and concrete durable journal. No public generic verifier, caller-success boolean or arbitrary journal callback participates in proof issuance.

The eventual module/crate split must retain private proof constructors inside that boundary. The codec leaf produces portable data and checked internal decode results; it does not provide public constructors for engine handles. The engine leaf consumes the frozen type contract; integration exposes authenticated handles only after the fixed verifier/journal join. A cyclic crate dependency is prohibited. Resolve the concrete module locations in the executable packets before dispatch.

Identifiers are distinct Rust newtypes: `SimulationId`, `ParticipantId`, `SessionId` (16 bytes), `ConfigDigest`, `EnvelopeDigest`, `FactDigest` (32 bytes), `RecoveryGeneration`, `FenceTerm`, `EmissionEpoch`, `ChannelSequence`, `JournalPosition`, `Revision` (u64). Zero session IDs and zero active recovery/fence generations reject. Increment overflow is terminal and cannot wrap. LP identifiers remain u32; ticks remain full-width u128. Cryptographic digests never replace full structural event identity for equality.

The immutable activation manifest contains manifest version u64, parent manifest digest (all-zero only for provisioned genesis), effective committed cut ID, simulation ID, protocol/schema versions, complete ordered participant/key membership, LP ownership/fence map, partition/topology, model/payload/RNG versions, negotiated limits and cut coordinator identity. A manifest digest binds its canonical complete bytes. Activation records a fresh session and strictly increasing durable generation before traffic. For an active owner, source `FenceTerm = Scoped.ownership_epoch = EmissionEpoch`, preserving the existing native validation rule. The namespace is the big-endian u128 interpretation of SimulationId. Recovery generation/session identify activation independently. Destination fence binds the current receiving LP owner. Rank, address and transport connection are routing metadata. Test provisioning uses fixed public-fixture keys in isolated test directories; production secret acquisition, rotation and deployment have separate authority.

## 2. Exact adapter surface

The following signatures are the proposed Rust boundary; none exists at this source baseline. `Record` types below are signed portable data with bounded canonical bytes. `Verified*` types have private fields, no public constructors, no serde implementation, and a private driver/session/journal binding invalidated by restart. The driver verifies signatures, membership, fences and durable prerequisites before returning a handle. A handle from another driver or expired activation rejects at every adapter entry point.

```rust
new_external(partition: PartitionPlan, topology: BTreeMap<LpId, Vec<LpId>>,
    processes: BTreeMap<LpId, P>, options: OptimisticOwnedOptions,
    driver: ExternalAccountingDriver, codec: C)
    -> Result<ExternalOptimisticRuntime<P, C>, ExternalOpenError>;
resume_external(driver: ExternalAccountingDriver, codec: C)
    -> Result<ExternalOptimisticRuntime<P, C>, ExternalRecoveryError>;

seed_external_roots(&mut self, inputs: Vec<ExternalRootInput>)
    -> Result<ExternalSeedRecord, ExternalOperationFailure>;
close_external_initial_inputs(&mut self)
    -> Result<ExternalInputClosedRecord, ExternalOperationFailure>;
admit_external(&mut self, delivery: VerifiedExternalDelivery)
    -> Result<ExternalAdmissionRecord, ExternalOperationFailure>;
acknowledge_external_admission(&mut self, admission: VerifiedExternalAdmission)
    -> Result<(), ExternalOperationFailure>;
receive_external_retirement(&mut self, cancellation: VerifiedExternalCancellation)
    -> Result<ExternalAdmissionRecord, ExternalOperationFailure>;
run_external_until_with_budget(&mut self, until: Tick, budget: usize)
    -> Result<ExternalRunProgress, ExternalOperationFailure>;
acknowledge_external_retirement(&mut self, retirement: VerifiedExternalRetirement)
    -> Result<(), ExternalOperationFailure>;
pending_external_records(&self) -> Result<Vec<ExternalOutboundRecord>, ExternalOperationFailure>;
applied_external_retirements(&self) -> Result<Vec<ExternalRetirementRecord>, ExternalOperationFailure>;
prepare_external_cut(&mut self, plan: VerifiedExternalCutPlan)
    -> Result<ExternalPrepareRecord, ExternalOperationFailure>;
apply_external_cut(&mut self, decision: VerifiedExternalCutDecision)
    -> Result<ExternalCutReport, ExternalOperationFailure>;
```

Initial roots are authorized by the immutable manifest's ordered initial-input digest/count; seeding reserves lifetime roots/incarnations durably before execution, checks actual source LP and accepts exact retries only. Closing inputs commits completeness against that fixed set; no later root injection or reopening is allowed. Initial-open/closed state contributes to cut eligibility.

The fixed driver surface is `open(ExternalProvisioning, JournalDirectory, DriverLimits) -> Result<ExternalAccountingDriver, ExternalOpenError>`, `verify_delivery(&[u8]) -> Result<VerifiedExternalDelivery, ExternalVerificationError>`, `verify_admission(&[u8]) -> Result<VerifiedExternalAdmission, ExternalVerificationError>`, `verify_cancellation(&[u8]) -> Result<VerifiedExternalCancellation, ExternalVerificationError>`, `verify_retirement(&[u8]) -> Result<VerifiedExternalRetirement, ExternalVerificationError>`, `verify_cut_plan(&[u8]) -> Result<VerifiedExternalCutPlan, ExternalVerificationError>`, `verify_cut_decision(&[u8]) -> Result<VerifiedExternalCutDecision, ExternalVerificationError>`, `verify_readback_request(&[u8]) -> Result<VerifiedExternalReadbackRequest, ExternalVerificationError>`, `readback(VerifiedExternalReadbackRequest) -> Result<ExternalReadbackResponse, ExternalOperationFailure>`, and `export_checkpoint() -> Result<ExternalCheckpoint, ExternalOperationFailure>`. JournalDirectory selects the reviewed fixed backend, never an arbitrary journal trait. Provisioning binds manifest/trust and participant signing credentials; transport cannot manufacture provisioning or verifier handles. Record issuance after commit stays private to the engine/driver boundary. Export is observational and produces only a complete committed checkpoint. After constructor ownership transfer, the runtime exposes `verify_external_record(&self, bytes: &[u8]) -> Result<VerifiedExternalRecord, ExternalVerificationError>`, delegating to its fixed driver and returning a closed enum of Delivery/Admission/Cancellation/Retirement/CutPlan/CutDecision/ReadbackRequest. It also exposes observational `readback_external(VerifiedExternalReadbackRequest)` and `export_external_checkpoint()` with the driver result types above. The runtime additionally exposes `prepare_external_manifest(VerifiedExternalManifestProposal) -> Result<ExternalManifestPrepareRecord, ExternalOperationFailure>` and `activate_external(VerifiedExternalManifestDecision) -> Result<ExternalActivationRecord, ExternalOperationFailure>`. Its delegated verifier enum includes ManifestProposal/ManifestDecision/RecoveryOpen, with private fixed-driver validation against the current trusted manifest and effective committed cut; unsigned proposals cannot issue handles. A fresh genesis runtime activates only against its separately provisioned complete genesis manifest and durable genesis checkpoint. Every non-genesis recovery remains standby until the successor activation transaction commits. A ManifestProposal handle verifies the coordinator's signed ManifestPrepare record for that exact proposed manifest and effective committed cut; each other participant signs its own matching prepare. Coordinator initial preparation is an internal fixed-driver operation tied to the approved provisioning/recovery request, not an arbitrary proof-minting callback. No mutable driver accessor, raw journal handle or signing callback escapes; adapter operations recheck the verified handle against current activation/revision before mutation.

`receive_external_retirement` acknowledges durable cancellation admission, not applied retirement. Budgeted execution applies cancellation, compensates model/RNG/history, retains authoritative descendant antis and commits an applied-retirement fact before `applied_external_retirements` returns it. `acknowledge_external_retirement` records that exact fact and atomically releases only the latest Present successor whose complete ancestor-cancellation closure is satisfied. No separate public release operation can bypass this closure. Polling never changes counters, revisions or obligations.

`ExternalRunProgress` contains budget consumed, executed/retired event counts, pending/replay counts, blocked/released/outbound counts, committed revision and floor; counts describe actual committed work. `ExternalOperationFailure` contains outcome `PreflightRejected | Compensated | Poisoned | CommittedCleanupFailed | CommitOutcomeUnknown | CommittedReceiptPending { fact_id }`, typed cause, pre-operation revision, last committed revision, committed progress and health `Healthy | RecoveryRequired | Poisoned`. Causes include `Malformed`, `LimitExceeded`, `UnsupportedVersion`, `Unauthenticated`, `UnknownMember`, `WrongSimulation`, `ConfigMismatch`, `StaleSession`, `StaleFence`, `IdentityConflict`, `BelowCommittedFloor`, `Capacity`, `Paused`, `MissingDependency`, `IncompleteCut`, `Storage`, `Model`, `Recovery`, `Overflow` and `Poisoned`. Storage uncertainty always fences publication and further mutation until durable readback/recovery. No error result fabricates rollback of an already durable commit.

## 3. Canonical wire format

The application record is independent of protobuf/MPI encoding. gRPC transports an opaque canonical byte string; protobuf uint64 fields cannot carry ticks or authorize proofs. MPI transmits the identical byte string. V1 rejects unknown kinds, unknown versions, noncanonical encodings, trailing bytes and duplicate sorted entries. All integers are unsigned big-endian, fixed width; byte strings and arrays have u32 lengths checked before allocation. IDs and digests are fixed width. No optional-field omission or language-map iteration order affects signed bytes.

Common prefix: ASCII `KAIROS-EXT` (10 bytes), wire version u16=1, kind u8, algorithm u8, key ID 16 bytes, simulation ID, config digest, issuer participant ID, issuer session ID, recovery generation, followed by kind-specific body. The signature is over this complete prefix/body with the record-kind domain tag fixed by kind. The final fixed-width signature is not included in its own preimage. Digest is SHA-256 of `KAIROS-EXT-V1 || kind u8 || complete prefix/body`; each body's referenced envelope/fact digest includes the complete original record identity. Exact signature/hash choices and package pins remain subject to security review in section 8.

Kinds: Positive=1, Cancellation=2, Admission=3, AppliedRetirement=4, Release=5, Pause=6, Prepare=7, CutDecision=8, CutApplied=9, ReadbackRequest=10, ReadbackResponse=11, Activation=12, MigrationPrepare=13, MigrationDecision=14, MigrationApplied=15, RecoveryAuthorization=16, Paused=17, Seed=18, InputClosed=19, ManifestPrepare=20, ManifestDecision=21, RecoveryOpen=22. Cut decisions encode Commit or Abort; no omission means abort. Each kind has one fixed positional schema, to be captured as independently checked golden bytes before implementation acceptance. Transport heartbeats cannot replace any record kind.

Positive/Cancellation body: source LP u32, destination LP u32, source fence u64, destination fence u64, scoped authority namespace u128 and ownership epoch u64, emission epoch u64, complete logical ID, incarnation u64, tick u128, payload schema ID16/version u32, payload length u32, exact payload bytes; channel source/destination participant IDs and sequence u64. Logical ID uses tag0 Root `(root source LP u32, root sequence u64)` or tag1 Output `(complete parent ordering key, ordinal u32)`. A parent ordering key recursively includes tick u128, actual source LP u32 and its complete logical ID. Decode uses a bounded iterative stack and checks depth before allocating; a flattened root-plus-ordinal path is insufficient because it loses ancestor ticks/sources. Canonical depth-first encoding follows this exact tagged grammar. Cancellation additionally references exact predecessor positive digest and transition ID `(issuer participant, issuer session, recovery generation, sequence)`; it carries the predecessor's complete identity, complete successor descriptor `Present { full identity, destination, tick, payload, digest } | Absent`, and sorted exact ancestor cancellation transition IDs. Never-delivered blocked intermediate successors retain their complete descriptors and ancestor closure, so delayed proof cannot release a later successor without unresolved predecessors. Different payload, destination, ancestry or tick under the same incarnation is an identity conflict, never a duplicate. Cancellation without a previously received positive still durably establishes exact tombstone/retirement obligations.

Admission body: exact envelope digest and full identity, source/destination sessions/fences, durable fact ID `(participant, session, generation, journal position)`, fact digest, resulting revision, admission classification `PositiveQueued | CancellationQueued | PositiveTombstoned`. AppliedRetirement adds transition ID, predecessor digest, effect `PendingRemoved | ExecutedRollback | AntiBeforePositive`, retained tombstone identity, complete descendant cancellation IDs/digests, durable after-state digest and revision. Release binds reserved successor digest and the sorted complete dependency-closure set of exact applied-retirement facts. Repeated requests read back the original fact/classification and exact signed record bytes rather than allocating another sequence, incarnation, capacity slot or revision. Duplicate observation is local response metadata only, not another signed classification. A positive arriving after a cancellation tombstone is durably accounted as PositiveTombstoned and never queued. `FactDigest` hashes the separately encoded committed fact statement (kind-specific identity/effect/after-state/revision), excluding the digest and signature fields themselves; record digest instead hashes the complete canonical signed-record preimage. These are distinct types and preimages; no self-referential digest exists.

Default negotiated maximums: record 8 MiB, payload 1 MiB, ancestry depth 128 (the existing native hard limit), participants 256, LPs 65,536, dependencies per fact 4,096, checkpoint section 64 MiB, total checkpoint 1 GiB, channel window 4,096 records, journal 4 GiB per participant. Reaching journal capacity stops admission before mutation; retained proof obligations cannot be evicted to make room. Limits are immutable manifest inputs, checked with overflow-safe arithmetic before allocation and accounting mutation. A scenario exceeding bounds fails admission/activation explicitly; no silent truncation. Huge closures/checkpoints require a separately versioned chunk protocol, not an unbounded v1 exception.

### Canonical manifest field order

The manifest's exact positional order is: domain literal `KAIROS-MANIFEST-V1`; manifest version u64; predecessor Digest (zero only genesis); effective cut tag0 Genesis or tag1 CutId; SimulationId16; wire version u16; model schema Id16/version u32; payload schema Id16/version u32; RNG algorithm Id16/version u32/stream-map Digest; coordinator participant Id16; ordered membership count u32 and each `(participant Id16, key Id16, Ed25519 public key32, TLS certificate SPKI Digest)`; ordered initial active Member[]; partition LP count u32/lookahead ticks u128; sorted complete entity-owner array `(entity index u64, generation u32, LP u32)`; ordered segment array `(LP u32, sorted complete entity IDs[])`; topology array `(LP u32, sorted neighbor LP u32[])`; initial input Digest/count u32; limits in the exact order below, each u64. ConfigDigest hashes this complete domain-prefixed manifest bytes. Signed successor decisions bind the whole manifest; no signature field is recursively included in the manifest itself.

Limit order: record bytes, payload bytes, causal depth, participants, global LPs, dependencies per fact, checkpoint-section bytes, total checkpoint bytes, channel records, journal bytes, local LPs, pending events, history events, tombstones, output batch, outbox entries, transition entries, receipt entries. Values must fit the target usize/u32 where used and satisfy native invariants. Namespace/fence/emission maps derive exactly from SimulationId/initial Member owners; constructor options must match the actually activated manifest's maps and these limits. A standby reservation cannot change those maps; it requires the successor-manifest protocol before activation. Partition owners/segments must match `PartitionPlan` deterministically reconstructed from the complete EntityId set and lookahead; mismatch fails activation. Every LP appears exactly once in ownership and topology; unknown entities/LPs or duplicate assignments reject. Initial input digest hashes domain `KAIROS-INPUTS-V1` followed by the complete ordered bounded canonical root-input data, so digest/count cannot authorize an arbitrary new seed set. Limits and complete input data are retained with provisioning/checkpoints. Genesis uses only the separately provisioned trusted manifest, never a caller assertion about trust. A successor version is exactly previous+1 with checked overflow and requires the unanimous effective-cut decision.

### Control-body field order

These are positional body layouts in the stated order, not protobuf schemas. `Id` is16 bytes, `Digest` is32, `Tick` isu128, and named counters/terms areu64 unless explicitly specified. Arrays begin with u32 count and sort lexicographically by their complete canonical identifier; duplicate entries reject. Nested bytes begin with u32 length. Enum tags areu8 and only the listed values accept.

`TransitionId = participant Id, session Id, generation u64, sequence u64`; `FactId = participant Id, session Id, generation u64, journal position u64`. `CutId = coordinator TransitionId`. `Owner = participant Id, session Id, generation u64, LP u32, fence u64`. `Channel = source Id, destination Id, first captured sequence u64, last captured sequence u64, records Digest`; an empty channel has first=last=0 and the digest of the empty ordered set. Sequence0 never identifies traffic. `Member = participant Id, session Id, generation u64, sorted Owner[]`. `PrepareRef = participant Id, complete signed Prepare record bytes`; `FactRef = FactId, FactDigest, complete signed original fact-record bytes`. The complete nested signed bytes allow authentication without assuming remote WAL access. Bounded nested records count against the aggregate record limit. `Bound = tag0 Finite + Tick | tag1 Terminal` (Terminal has no integer). `CheckpointRef = checkpoint generation u64, complete section-manifest Digest, total length u64`. It always names a complete previously committed checkpoint, excluding the currently issued fact/transaction. Prepare first commits a complete reconciled checkpoint, then separately commits its prepare fact referencing it while state remains frozen. Genesis checkpoint is installed before activation; no empty checkpoint masquerades as complete. The durable WAL/database suffix from that checkpoint through the referenced fact reconstructs the exact after-state. Cut/migration application commits its after-image before a later complete checkpoint incorporates those facts; no current fact hashes a checkpoint containing itself. `DurableRef = FactId, FactDigest, resulting revision u64, committed after-state Digest`.

For any own DurableRef, its own FactDigest is computed from `KAIROS-FACT-V1 || kind || common prefix || complete body with that own FactDigest field omitted`; other referenced fact digests remain. The stored committed fact statement uses these exact bytes. `committed after-state Digest` hashes complete engine/model/RNG/graph/reservation state with newly issued fact digest/signature/readback metadata excluded from that digest's preimage. The journal transaction digest separately covers the full after-image and facts once constructed. This prevents a fact digest or after-state hash from depending on itself; retained prior facts remain bound by the transaction/checkpoint manifest. No self-digest or self-signature is included. Other fields including position/revision/after-state digest are assigned before durable commit. Final record digest/signature are computed from the complete body including that fact digest after commit. Identical fact retries return retained original record bytes; regenerated signatures must reproduce the same canonical record or fail, never create another accounting fact.

A terminal cut encodes drained global quiescence separately; it cannot invent Tick::MAX+1 or discard unresolved obligations. Initial v1 implementation may return UnsupportedVersion for terminal collection until an explicit final-state acceptance oracle exists. Abort must repeat the previous floor and does not authorize reclamation. PrepareRef[] completeness and one exact manifest participant per reference are mandatory for Commit; Abort still binds the exact pause/member set and preserves every retained obligation.

## 4. Durable transaction and recovery

One writer owns each participant's durable journal and engine state. Model effects remain unpublished until commit. Each native atomic unit (a complete selected positive round or one charged rollback/anti step) stages complete before/after state (model, RNG, engine/accounting and outbound facts), validates capacity/closure, then writes one bounded atomic logical transaction. A transaction's durable commit marker covers expected pre-state hash/revision, every after-image section and exact output facts. Commit precedes in-memory after-image publication. A commit-before-publication crash installs the after-image without repeating the handler. Model callbacks cannot perform irreversible external I/O; visible effects are journaled outbound intents published after commit. Logical rollback never reverts the authoritative journal/fence history. Poison/validity changes are durable before any further operation. Post-commit Drop/cleanup failure retains the commit and a poisoned cleanup report. A receipt is signed/returned only after commit durability is confirmed. Signing failure after commit permits exact readback/retry, never undo or a replacement fact.

The concrete storage backend and filesystem crash guarantees must be accepted before activation. A checksum by itself does not provide atomicity or durability. Recovery distinguishes incomplete uncommitted tails from corruption of committed data and fails closed on the latter. No successful storage claim follows from a buffered write, ordinary rename or `sync_all` alone without the specified directory/recovery/platform protocol and real process-kill evidence. V1 has no distributed consensus/automatic coordinator failover; unavailable durable storage stops progress.

Checkpoint sections are required: manifest/activation/fence history; model and component generations; RNG algorithm/state; LP clocks/pending/replay; reversible history/exact outputs; tombstones/conflicts; graph transitions/ancestor barriers; lifetime root/incarnation/epoch reservations; ready/blocked/in-flight outbox; admissions/retirements/releases and exact retained remote signed facts; counters/revisions/channel frontiers; last horizon, both initial-input closure states, runtime health/poison, per-LP validity epochs, exhausted allocator sentinels; common committed floor and cut/migration decisions. Each has a version, bounded length and digest, with a complete ordered section manifest and transaction digest. Missing, duplicate or incompatible sections reject.

Recovery loads only a committed complete checkpoint and verified committed database/journal suffix. It invalidates old local handles and opens in standby `RecoveryRequired`, reserving a fresh session and strictly greater generation/fence durably. This is a RecoveryOpen proposal, not live Activation. Standby permits only authenticated recovery/reconfiguration/readback controls; it cannot execute a model, admit live work, publish retained outbox work or issue RecoveryAuthorization. The immutable current manifest is not mutated. Only complete paused preparation, unanimous successor-manifest commitment and durable application may install the new tuples and enable live Activation. Missing participant/coordinator, unknown durable outcome or unprovable old-owner fencing leaves standby blocked; no timeout or automatic takeover exists.

RecoveryOpen binds the participant's complete old and proposed new Member tuples, including every owned LP. Participant identity, trusted key and LP ownership set must remain identical; session/generation advance consistently and every owned LP fence strictly increases. Partial member/LP updates reject. RecoveryOpen is authenticated using the previously authorized participant key and old manifest digest while explicitly carrying the proposed new session/generation/fence. Its fixed driver must have verified exclusive previous-journal ownership and retained complete state before committing that proposal. Peers permit this narrow recovery-only control under that participant key; they do not treat its proposed tuple as a live owner. The paused recovery cut has the old complete membership plus the exact signed replacement proposal, permits the standby participant's prepare bound to both tuples, and commits the unchanged previous floor (no collection). Then every current participant signs ManifestPrepare for exactly the successor manifest containing the proposed tuple, parent digest and effective recovery cut. ManifestDecision commits that unanimous set. Only after durable adoption may the recovered owner publish Activation and reauthorize retained original records under the new config. Old live records remain fenced; original manifests/facts remain historical evidence. A coordinator crash stays blocked unless its original durable decision store is recovered and this same complete reconfiguration path can be proven; this v1 design provides no alternate coordinator, new leader election or timeout progress. Live traffic under old sessions/fences rejects. Historical retry/readback is a separate operation: it returns a retained original authenticated committed fact if the old issuer was authorized at that fact's commit; it cannot admit new work under old authority. Retained unadmitted outbox work survives restart through RecoveryAuthorization: the current fenced source owner signs the exact original envelope bytes/digest, original authorized manifest/session/fence, committed source outbox fact and current activation/fence. The receiver verifies the full historical manifest chain plus current source ownership, and admits the original identity once under this current recovery authorization. It does not accept arbitrary old-session traffic, rewrite payload/identity, or allocate a replacement incarnation. A changed destination owner additionally needs the exact committed migration routing decision. The nested original envelope remains signed by its original authorized key; reauthorization is a separate signed kind with current authority. Receiver fact binds both digests, and retries retain the same durable admission. Complete graph/reservations prevent root/incarnation reuse after restart. Compaction retains all records needed by the latest committed checkpoint, complete common cut and outstanding historical retry/retirement obligations. Checkpoint replacement and WAL truncation must share a crash-safe generation protocol; collection cannot delete the only committed restore point. Model restoration failure poisons and fences the runtime; no successful receipt/cut follows.

| Crash point | Recovery oracle |
| --- | --- |
| Before admission commit | No successful receipt; exact retry admits once. |
| After admission commit before ACK | Same fact/digest/position; no new revision. |
| Before/after effect commit | Restore before or after entire model/RNG/accounting transaction; no unjournaled published effect. |
| Before/after retirement commit | Before keeps successor blocked; after returns same complete retirement fact and descendant antis. |
| Before/after release commit | Before keeps blocked; after retains the same released successor until its admission. |
| Storage ambiguity or corrupt committed bytes | RecoveryRequired/Poisoned, no publication or floor advance. |
| Restart/migration | Reject stale live work; authorized historical exact facts remain retrievable. |

## 5. Coordinated cut

V1 uses a provisioned fixed coordinator and complete fixed membership. Cut ID binds coordinator generation/sequence, previous floor, manifest, complete participant/session/fence set and requested candidate. Cut coordination is authenticated and durable; an all-reduce result is advisory until the complete decision commits.

1. Coordinator durably records Pause. Participants stop model mutation, new emissions and new live admission; snapshot outgoing/incoming channel frontiers and retain every positive, anti and control obligation. Read-only exact retries remain permitted. Pause receipt includes frontier/revision/floor and manifest identity.
2. Reconcile captured channel windows. Buffered messages can be durably staged as cut input without model execution. A fenced reconciliation transaction accounts each captured message exactly once; it advances revision before the final prepare snapshot. No prepared revision can subsequently change. Sender retained records and receiver staged/admitted records reconcile by exact sequence/digest, including lost ACKs and cancellation/control traffic. Missing/conflicting frontier records block prepare; no unobserved message is presumed delivered.
3. Each participant commits Prepare containing final revision, complete channel frontier/digest reconciliation, complete checkpoint digest, local minimum including pending/replay and unresolved reversal/proof obligations, blocked/reserved successor and all in-flight obligations. Native equality and predecessor30/successor25 protection remain. Retained history by itself does not constrain the minimum: strictly-below-floor history becomes collectable only after common commit and all necessary reversal/proof obligations are closed. Prepare evidence authenticates actual complete accounting, not caller minima.
4. Coordinator verifies one exact Prepare from every manifest participant and commits a common decision containing the entire ordered prepare set/digests and common floor. Floor never decreases, never exceeds any conservative contributed minimum, and collects strictly below it. Empty workload has a separately encoded terminal bound, never u128 overflow.
5. Each participant authenticates the full decision, compares its frozen revision/frontiers, durably records application and only then collects/resumes. Equality remains reversible. A crash queries the same durable decision; no alternate commit under the same cut ID exists. Missing coordinator/member blocks progress. Abort is also durable and authenticated; it releases pause only after exact abort readback. No timeout/unilateral floor or abort is authority.

Local minimum algorithm: reject preparation if poisoned or either initial-input set remains open. Enumerate every queued positive/anti/replay event tick; every ready/in-flight outbox tick (including lost ACK); every current blocked local/remote Present successor tick; every unresolved ancestor predecessor-positive tick; each requested but unapplied source retirement predecessor tick; each unapplied receiver retirement predecessor tick; every captured undelivered channel record's relevant tick and any proof/control record's referenced event obligations. The contributed finite bound is the minimum of these ticks and the requested finite candidate. Empty event/proof obligation sets contribute that requested candidate, not an invented infinity. The candidate must be at least previous floor and consistent with the collectively closed initial-input/horizon contract. The coordinator selects the minimum of all exact contributions and verifies complete channel reconciliation; it never treats missing input as infinity. Retained reversal/proof bundles are separately protected across all participants until their shared dependency is resolved and the strict floor permits reclamation. This mirrors native obligation enumeration rather than using all retained history as a minimum.

Admission reconciliation during step 2 is the only bounded accounting mutation after Pause; it ends before Prepare. This resolves the otherwise inconsistent requirement to freeze revisions while draining messages. No arbitrary new traffic is accepted in this window. Proof retention is governed by complete cuts: lost ACKs and old30/new25 predecessor proof cannot be discarded merely because its timestamp exceeds the new successor's minimum.

## 6. Migration

Migration is a complete LP ownership-unit transfer at an accepted paused boundary: model/component generations, RNG, pending/replay/history, root reservations, transition/dependency graph, tombstones, receipts and every retained/blocked obligation. Coordinator durably commits old-owner revocation and new strictly greater fence as one decision before the new owner activates. Old owner durably fences before transfer acceptance; if that cannot be proved, migration blocks. New owner verifies complete section/digest manifest, imports durably and signs MigrationApplied. No simultaneous two-owner authority, partial model-only migration or timeout takeover exists. Channel remapping retains original historical identities and readback routes under the decision. Migration and key rotation create a successor immutable manifest version with parent digest and effective cut. All current authorized participants sign the exact manifest prepare, and the coordinator commits the full ordered unanimous set in ManifestDecision. No manifest mutation, coordinator-only membership takeover or unsigned key replacement is permitted. The old manifest remains available for original fact verification; new live traffic activates only after the common decision.
