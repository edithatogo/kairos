## ED data and parameter evidence boundary

Evidence supports a two-layer profile. Some observed task means, aggregate arrival/case-mix statistics, administrative endpoint semantics, and public mechanical examples have specific labelled uses. Primitive distributions, local resource calendars, ATS-conditioned triage work, reassessment, diagnostics decomposition, consultation response, cleaning tails, and abandonment patience remain unknown or require assumptions/direct local observation. Do not average synthetic, elicited, international, and Australian values into one parameter.

Before primitive fitting, record event start/end semantics, population/period, units, censoring, episode count, access authority, transformation, and whether a value is observed, elicited, fitted, derived, or synthetic. Keep `observed_range`, `scenario_range`, `parameter_uncertainty`, and `calibration_bounds` separate. Aggregate LOS/occupancy is not primitive active service. A distribution constructed around published moments remains synthetic/elicited unless the source supplies and supports a compatible full fit.

The missing Report 6 machine-readable files cannot be recreated from summary paragraphs. The missing Report 30 crosswalk cannot be recovered from eleven provisional IDs. This ledger records leads and limits, not recovered datasets. No access request or contact was made.

## Methods evidence for C0.3 oracles

The supplied Report 12 review supports bounded requirements:

- Keep primitive input fitting distinct from occupancy/outcome comparison. Censored records remain censored; competing-event incidence and time-to-event need separate validation.
- Use clamped replay only for permitted historical anchoring and calibration diagnostics. Check for parameter ridges and abstain from separately reporting confounded parameters; use later free-running data for predictive validation.
- Split chronologically and by episode/patient before fitting, selecting families, estimating routes, choosing weights, or tuning tolerances. A test period used for model changes is consumed; new claims require a later holdout.
- Distinguish simulation stochastic uncertainty from input-data/refit uncertainty. Resample at supported dependence units; label limitations if identifiers are unavailable.
- Prespecify endpoints, strata, units, coverage counts, and valid samples for W1/KS-type discrepancies. Do not default to a classical KS p-value for tied/clustered data; keep censoring/missingness visible.

These are method requirements, not validated numerical weights, tolerances, or a universal split ratio. Exact choices remain for the C0.3 oracles proposal and coordinator review before held-out outcomes are exposed.

## Dependency and compatibility evidence

Kairos `Cargo.toml` at the bound revision declares `rust-version = "1.76"`; C0.1 left that compatibility contract unchanged. The [official Arrow Rust 60.0.0 release notice](https://arrow.apache.org/blog/2026/09/29/arrow-rs-60.0.0/) says MSRV rose to Rust 1.88; the [60.0.0 release/tag](https://github.com/apache/arrow-rs/releases/tag/60.0.0) identifies commit `ef1fa15`. Arrow 60.0.0 therefore cannot satisfy the current 1.76 workspace MSRV. This is version-specific and does not prove Arrow support is impossible.

The existing owner-approved D1.2/ADR-0002 direction resolves the boundary: preserve Rust 1.76 for existing workspace packages; use Arrow/Parquet 60.0.0 only as the dated candidate for a separately reviewed package at candidate floor 1.88; require Track 04 schema/interoperability agreement and actual package/Track 25/30 review before adding the dependencies. This is a versioned design handoff, not adoption or a claim that the future package is already supported. The current policy names Arrow/Parquet 60.0.0 (MSRV 1.88); the official release notice confirms that floor. No Cargo file changed.

An isolated alternate candidate trial was run for Arrow and Parquet 54.3.1 with defaults disabled and IPC/Arrow features enabled. `rustup run 1.76.0 cargo check` passed for a minimal native-host RecordBatch crate, but a full `cargo metadata` scan under Cargo 1.76 encountered the target-specific `wit-bindgen 0.57.1` manifest requiring Cargo's edition-2024 feature. This limited trial is not an owner decision, full target-matrix check, complete transitive-license audit, or justification to replace the approved 60.0.0/separate-package direction. Its manifest, generated lock, log, and tree are retained under the local ignored C0.3 trial artifact directory.
