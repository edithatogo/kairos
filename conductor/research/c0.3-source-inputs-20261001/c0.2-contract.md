# C0.2: calibration data and event contract

**Status:** Coordinator draft, ready for review. This freezes the parent-project
record semantics and schema proposal. It does not implement Rust/Arrow readers,
prove source conformance, or approve the Core 01 seed algorithm.

## Decision and boundary

C0.2 defines one versioned record family in
[`calibration-v1.schema.json`](calibration-v1.schema.json): mapping bundle,
dataset manifest, normalized trace event, trace exclusion, location interval,
parameter evidence, fidelity decision, isolated calibration probe, outcome
observation, residual, aggregate metric, and staged fidelity-policy update.
`trace_event.v1` preserves the
source event and its clocks; derived intervals and outcomes remain separate
records with lineage. Source semantic mapping strength, availability of a local
feed, and conformance of a local feed are separate claims. The supplied Report
30 crosswalk is absent, so its eleven IDs remain provisional and every local
availability value remains `unknown`.

The contract consumes [ADR-0004](../../decisions/ADR-0004-ed-clock-profile.md),
the calibration placement and adapter decisions in
[`ADR-0005-calibration-placement.md`](../../../libs/kairos/conductor/design/calibration/ADR-0005-calibration-placement.md)
and [`calibration-adapter-v1.md`](../../../libs/kairos/conductor/design/calibration/calibration-adapter-v1.md),
and the [C0 specification](../../tracks/empirical_calibration_20260925/spec.md).
Arrow physical encoding and executable ingestion validation belong to C1; C0.3
sets objective weights, scales, tolerances and inference validity. This contract
does not add runtime APIs, dependencies or numeric acceptance thresholds.

## Time origin, precision and ordering

Each timestamped dataset declares one explicit UTC origin. Preserve the raw
timestamp text, source precision, source offset or zone, clock role and lineage.
`occurrence_time` (the instant the domain event occurred), nullable
`source_recorded_time`, and nullable `message_created_time` are distinct. A
resource update or message timestamp cannot be substituted for event
occurrence. Lineage is `observed`, `derived`, `defaulted`, or `unknown`, with a
mapping/version reference; missing values stay null and carry an explicit
quality/status reason.

Normalize explicit-offset timestamps to UTC before checked subtraction from the
origin. The canonical relative tick is a nonnegative nanosecond `u128`: Arrow
uses 16-byte little-endian fixed-size binary; canonical JSON uses an unsigned
decimal string. Reject naive local time until an IANA-zone adapter defines DST
fold/gap behavior; reject pre-origin, overflow and unrepresentable
sub-nanosecond observations. Preserve minute precision as minute precision; do
not manufacture seconds. There is no silent truncation or rounding for observed
timestamps. Any future explicitly approved rounding policy must record its
version and count. The ADR-0004 ceiling rule applies to sampled model durations,
not observed timestamps. A date-only/coarse or timezone-ambiguous source time
cannot become a canonical event tick; preserve the raw event and clock value in
`trace_exclusion.v1` with its reason and lineage until a valid source-defined
instant can be established. It is not assigned an arbitrary interval midpoint
or midnight.

Canonical order is `(relative_ticks, case_key, occurrence, event_kind_rank,
source_event_key, source_order)`. The mapping bundle versions a unique,
cycle-free event-kind rank map. Stable source keys are required for input-order
invariance; source row order is the last tie breaker only. `case_key` is
pseudonymous and is never itself an RNG seed. `source_event_key` is unique
within a dataset; duplicates reject unless a versioned explicit deduplication
rule records the inputs and outcome.

## Raw events, intervals and episode endpoints

Retain the normalized mapped event even if a standards projection is lossy.
`event_kind` is a versioned vocabulary and includes distinct
`episode_end` and `physical_departure`; neither implies the other. The event
record retains raw task/event identity and nullable provisional/realized
disposition, plus knowledge-availability time and status where applicable.
Unknown disposition is not silently promoted to realized.

`location_interval.v1` is a separate interval record with start/end event
references and times, location key, source/derivation lineage, and interval
status. A missing end is open/unknown, not zero-length. Reversed intervals are
invalid; equal endpoints are retained only where the source semantics permit
them. A location transition requires the versioned local dictionary and
boundary rule before it can establish physical movement. Episode end and
physical departure remain separately nullable, separately sourced, and
separately countable.

## Report 30 provisional crosswalk

Report 30 supplies a provisional minimum field set, not the unavailable
downloadable crosswalk or evidence of any local feed. Preserve IDs `C0-F001` to
`C0-F011` only as external candidate references; they are not canonical case or
event keys. Standard editions below are the report's research baseline (FHIR R4
4.0.1, AU Base 6.0.0, AU Core 2.0.0, HL7 v2.5.1, NAPEDC 2026–27, OMOP 5.5),
not a claim that they are current/latest, implemented locally, or conformant.
Local availability is `unknown` for all rows.

|---|---|---|
| C0-F001 `episode_id` | Candidate grouping key; no canonical source mapping established in the supplied temporal subset | unknown |
| C0-F002 `subject_id` | Candidate subject reference; must be pseudonymized to `case_key` under a separately evidenced rule | unknown |
| C0-F003 `event_type` | Candidate controlled event vocabulary; map per source profile and retain raw code | unknown |
| C0-F004 `source_event_time` | FHIR partial (event-specific period); HL7 v2 EVN-6 exact when applicable/populated; AIHW partial milestone date/time; OMOP partial visit/detail bounds | unknown |

| C0-F006 `location_id` | FHIR Encounter.location.location exact semantically; HL7 PV1-3 partial pending local PL dictionary; AIHW establishment-level partial; OMOP care_site_id coarse/ETL-defined partial | unknown |
| C0-F007 `location_start_time` | FHIR Encounter.location.period exact semantically where physical granularity applies; HL7 reconstructed partial after verified movements; AIHW internal ED location unavailable; OMOP VISIT_DETAIL partial only when ETL supports it | unknown |
| C0-F008 `location_end_time` | Same source and boundary limits as C0-F007; null/open interval retained | unknown |

| C0-F010 `physical_departure_time` | FHIR final applicable location period partial subject to boundary; HL7 movement/end partial subject to boundary; AIHW METEOR 799756/799758 exact; OMOP partial and unsafe without ETL lineage | unknown |
| C0-F011 `source_record_id` | Candidate source-row reference; retain only in controlled local provenance, never publish as identity | unknown |

The exact/partial/unavailable labels describe semantic strength in the named
standard only. They do not establish a local source, field population,
transformation or conformance. Source-specific cautions: HL7 MSH-7 is message
creation, not event occurrence or source recording; A08 does not prove physical
movement and A03 does not always prove physical departure. FHIR meta.lastUpdated
is resource-version update, not event recording. AIHW episode end and physical
departure are distinct. OMOP visit end is not observed physical departure
without ETL lineage. Preserve source codes, mapping status (`exact`, `partial`,
`unverified`, or `unavailable`), standard edition and evidence reference.

## Outcomes, censoring and parameter roles

An `outcome_observation.v1` names the estimand/endpoint, risk start, last known
observation, optional event time, event-observed flag, event cause, censor
reason, observation window and lineage. It distinguishes left, right,
interval, unknown and not-censored status. Event time requires an observed
event; right-censoring requires a last-observed time; missing or censored is
never encoded as zero duration, completion, or a successful endpoint. Counts
for eligible, observed, censored, missing, excluded and unmatched records stay
visible in aggregates. No complete-case success claim may hide exclusions.

Each measured parameter declares one role: `exogenous`, `primitive`,
`clamp_only`, or `target`. Record units, bounds if evidenced, source/mapping,
time-of-knowledge, availability window, cluster identifiers, and observed vs
derived/defaulted status. `cluster_status` separates identified membership,
unknown membership and not-applicable membership; an empty cluster list alone
does not establish independence. Future outcomes cannot become features
available at prediction time. Cluster IDs describe the sampling/dependence
unit; do not silently treat clustered records as independent.

## Seed-purpose handoff to Core 01

The proposed versioned seed identity is
`(study_id, seed_schedule_id, replication_id, case_key, task_key, purpose)` with
separate stable purposes for service, transit, behavior and calibration work.
`candidate_id` belongs in experiment provenance, not this tuple: candidates in
a paired common-random-number comparison reuse the same `seed_schedule_id`; an
independent candidate schedule uses a distinct candidate-scoped schedule ID.
The mapping bundle records `coupling_mode` (`paired_common_random_numbers` or
`independent`) and `candidate_binding` (`shared_across_candidates` or
`candidate_scoped`) so the pairing choice is auditable. Purpose-specific streams
must not share mutable draw positions across purposes. IDs require documented
stable normalization. This proposal freezes logical identity, candidate pairing
and purpose separation; tuple byte encoding, root-seed treatment,
hash/derivation algorithm, stream version and draw-position contract require
Track 01 owner acceptance before execution. Mark `approval_status=pending_track01`,
with no inferred algorithm or runtime compatibility. Current Kairos
`derive_entity_seed(run_seed, EntityId)` is an entity-seed API, not approval of
this richer tuple. Never hash patient strings, wall-clock time or worker/thread
order ad hoc.

## Fidelity, ledgers, residuals and metrics

Resolve fidelity precedence at task admission: `(entity, subsystem)` override,
then entity override, subsystem default, global default. Freeze and report the
selected policy for each task. Change policy only at a quiescent boundary;
reject changes while tasks are active or suspended. The record vocabulary
includes `ShadowAnchored` and `FreeRunning`. `fidelity_decision.v1` records the
resolved scope/rank and admission time; `calibration_probe.v1` records the
observed-ledger frontier, immutable snapshot hash, independent probe identity,
anchor and input-provenance references, predicted-record references and the
invariant that observed-ledger mutation is false. `fidelity_policy_update.v1`
records staged/applied/rejected changes; applied updates require a named
quiescent boundary and take effect for later task admissions. These make policy
selection and probe isolation auditable records rather than prose-only
expectations.

Observed source events and anchors form an immutable observed ledger. A
prediction runs in an isolated probe context and cannot mutate, backfill, or
enter that ledger. An anchor may represent only a source-defined observed
transition. Store the raw task events, provisional/realized disposition,
knowledge-availability and source lineage alongside both records, without
conflating them.

`calibration_residual.v1` records observed and predicted ticks, endpoint,
study/candidate/replication/run/case/task/occurrence, fidelity, anchor role,
feasibility/censor status, seed schedule/purpose/map reference, mapping/
parameter/graph provenance and causal reference. Define the signed
residual as `predicted_ticks - observed_ticks`: positive means the prediction is
later/longer than the observed endpoint, negative means earlier/shorter. Store
sign and unsigned magnitude separately to avoid signed `i128` overflow. Capture the
unclamped prediction before any clamp. A missing/censored observed endpoint has
no numeric residual; it remains represented with status and counts rather than
zero or silent omission.

`calibration_metric.v1` records metric and algorithm version, endpoints,
strata/window/units, source and simulation counts, excluded/censored/missing/
unmatched/failed/infeasible counts, optional value, status, uncertainty and
provenance. W1 gives equal weight to each valid observation, aggregates equal
support values, and integrates the absolute empirical-CDF gap over consecutive
unique supports. KS D is `max_x |F_reference(x) - F_simulation(x)|`; it evaluates the maximum
absolute difference between right-continuous empirical CDFs at each unique
value in the union of both supports, after all mass tied at that value is
accumulated. These calculations use stable ascending numeric order and fixed
reduction order. No classical KS p-value is implied for clustered/tied records.
C0.3 owns objective weights, numeric
tolerances and inference validity. Empty/insufficient inputs have an explicit
status and no fabricated metric value.
