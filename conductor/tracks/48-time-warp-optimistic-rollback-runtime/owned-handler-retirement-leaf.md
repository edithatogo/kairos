## Fixed scheduling and transaction unit

Preserve ascending LP selection, one earliest eligible positive per owned LP up to remaining budget, antis first. The atomic positive unit is the entire selected round, not an independently committed prefix of its LPs. An anti or rollback-only/control step is one separate unit. Earlier committed units in the run call survive a later failure. Only owned LPs contain models, snapshots, queues, validity tokens and emitter allocators. Logical execution order still excludes authority/incarnation; every storage identity retains complete source authority and incarnation. Legacy LocalPreview behavior stays unchanged.

Before callback staging, check health, owned mode, horizon monotonicity, live sealed actual complete peers, selected metadata and checked own revision/selected-LP validity headroom. Rejecting before any callback costs zero and changes nothing. Entering snapshot/callback staging charges the selected round width once, even if the round later aborts; entering an anti/rollback step costs one. Restore/compensation adds no second charge. Budget never exceeds the caller value. A completed rollback step publishes replay work and accounted cancellation antis; if its budget is exhausted, defer the handler. Suffix rollback work is bounded by history/output/transition limits and counts as work rather than an uncharged continue.

Staging preserves original queues, history, known deliveries, cohort heads, counters, emitters, outboxes, reservations and receipts until publication. Use shadow allocator/accounting records. Capture before-model snapshots, then execute callbacks outside all lifecycle gates. Actual output fanout/destinations determine a post-callback batch preflight; do not require worst-case route reservations that reject an otherwise valid actual batch. Preflight all actual roles and capacities, then reacquire canonical deduplicated actual-peer gates, revalidate liveness/configuration/metadata/headroom and publish the whole unit. Output source must equal the executing owned LP; output ticks/complete ancestry are strictly future, routes are global, local outputs queue once and remote outputs stay only in the source outbox. Never allocate a foreign emitter or create remote model/queue mirrors.

All model operations, including snapshot, Snapshot::clone, handler, restore, Snapshot Drop and process destructors, occur outside lifecycle guards. Cloning/dropping a historical or temporary snapshot under a guard is forbidden. Stage/detach snapshots without destruction during guarded publication; dispose afterward. Catch individual unwinding callbacks. Abort/double-panic recovery is outside the recoverable contract.

On post-callback rejection, restore every mutated/restorable LP in the selected unit outside gates. Preserve unpublished protocol state and restore logical model/RNG, but do not rewind model-owned validity epochs. Then acquire only the actual local own gate to advance pre-reserved validity epochs for touched/compensated LPs and one checked own revision; report an aborted-step observation in the detailed failure, without an unbounded internal failure ledger. Foreign peer death cannot block this narrow local cleanup. It issues no native send/admission/retirement fact, changes no emitter/queue/history/reservation/receipt or committed execution counter, and does not advance horizon or input closure. Snapshot capture failure without a restorable before-state poisons that participant; restore, clone/cleanup or own-gate failure also poisons. Compensate earlier restorable LPs; never claim validity unchanged after callbacks. If publication succeeded but cleanup Drop panics, retain the committed unit and report its poisoned cleanup failure.

Successful first publication in a run sets horizon and both initial-input closure flags under the same canonical guard. Idle, budget-zero and failed-first-unit calls leave horizon/closure unchanged. One publication advances own revision once and each affected local LP validity epoch once; affected includes local enqueue/dequeue/model/history/tombstone changes, not a remote destination. Compensation has its separately specified own revision/validity change. Admission/ACK/control exact retries allocate nothing and advance no revision/epoch.

## Reachable retirement protocol

Rollback knows an obsolete positive P before replay knows N, so receiver retirement requests are successor-independent cancellation requests. Remove the unreachable proposed Replacement disposition and optional successor from receiver requests/capabilities. This does not remove replacement behavior: replay commits actual N and its bounded source ancestry/dependency on P cancellation. No fake successor, public unchecked constructor or budget-dependent request shape is allowed.

Mint an immutable cancellation request for each obsolete output version during the charged rollback step and retain the exact anti. Source intent history is P(Present) -> A(Absent) -> N(Present), where A is a real bounded intent with no delivery. A binds cancellation of P; N inherits every unresolved cancellation ancestor. If N is superseded before P completes, mint cancellation of N and make N2 depend on both obligations. Applying P closes only P's request and cannot release N2 while N is unresolved. Only the current latest positive with every required cancellation applied can be Ready; superseded versions never briefly become Ready. If all obligations complete before future N exists, N may be Ready immediately. Changed payload/tick/destination and replay emitting fewer/no outputs use this same protocol.

A repeated no-output replay while the cohort remains Absent coalesces the same head/request/completion: no new intent, anti, receipt or ID, and no extra graph-specific revision. A real handler/rollback publication still advances its documented own revision once. A new absence node exists only after a new Present version actually committed and later became obsolete. The Absent node's ID is its cancellation request ID, with predecessor P; no separately sequenced request ID exists.

A blocked LOCAL successor is retained in its Present intent outside executable queues and reserves one max_pending_events slot. Its tick constrains local/minimum obligations. Completion promotes it once using that reserved slot, with preflighted destination epoch/revision and no new capacity. Supersession releases the old reservation and adds actual anti/new demand through one complete net-delta preflight. blocked_positive_count includes local and remote blocked presents; reserved_pending_count exposes local blocked reservations. Report/progress pending positives include blocked local presents and pending-event pressure includes their reservations. pending_events(lp) remains actual queue entries only. Runnable selection and budget_exhausted consider actual eligible executable work, so blocked-only work is pending but not runnable/exhausted.

Each source intent has a privately issued checked ID, one parent link within its exact source/authority/logical cohort and at most one associated cancellation request. A cohort-head map indexes actual bounded nodes; it is not a second unbounded ledger. Walk ancestors with a bound no greater than retained node count, detecting missing/forked/cyclic records. Do not materialize unbounded duplicated dependency graphs. Root cohort reservations remain for issuer lifetime and continue to consume their original transition slot, even after ACK/GVT; they prevent caller sequence reuse but cease constraining GVT once obligations complete. Output intents/edges may prune only by the group rule below. ID sequence never wraps or reuses.

Every anti ticket privately binds its actual immutable request. Request-first and anti-ticket-first reception use one canonical receiver request/admission record and queue the anti once. Validate actual sender/old receiver, registered witness/generation, complete configuration/authority, predecessor bytes, anti kind/identity and GVT before caches or mutation. Admission means queued/accounted only. A budgeted anti step removes a pending P or rolls back P's executed suffix, or proves P absent, installs exact tombstone protection and retains induced descendant antis in actual local queues/source outboxes. Only then mint applied retirement proof. Retire even a blocked predecessor through its actual receiver; missing positive admission ACK is not proof no old ticket escaped.

The all-unresolved pending request poller includes local self-requests. Exact receive_native_retirement(local_request) validates the retained actual request and returns the bundle's stable queued-anti capability without requeueing/allocation. acknowledge_native_admission(local_anti_cap) validates that bundle and is an exact no-op; it never completes retirement. Actual local anti application atomically installs protection/removes effects, retains descendant antis and completes its own source dependency, then exposes applied proof. Repeated applied readback/acknowledgment is a no-op. No local positive admission capability or transport ACK obligation is manufactured. Actor/liveness/GVT checks precede every cache readback.

The cancellation request reserves eventual tombstoned positive readback when P has never arrived. If P arrives while its anti is pending, admission uses that reserved receipt slot and actual pending capacity; a full pending queue can reject unchanged. After cancellation applies, a late P creates no queue entry and reads the reserved Tombstoned capability. An existing Pending admission capability remains immutable/historical after execution or tombstoning; exact retry verifies current retained accounting before returning it. Likewise, the original anti admission capability remains its original queued readback after application. Neither admission capability proves retirement.

Applied proof binds cancellation ID, exact predecessor positive/anti and actual source/old receiver, applied revision and effect. Source acknowledgment closes exact predecessor positive and anti obligations even if their admission ACKs were lost, moves the pre-reserved ACK records to retained completion readback, and recomputes latest readiness. Late exact positive/anti ACKs succeed without allocation/revision. Admission ACK alone never unblocks a replacement. Duplicate applied proof returns/ACKs the same completion with no allocation/revision. Validate actual issuers and pre-GVT work before every cache readback. Wrong source, old receiver, cancellation, bytes or ancestor completion cannot close another obligation.

## Unique-record capacity accounting

The existing max_transition_entries bounds lifetime root/source positive intent nodes, absence/cancellation nodes and incoming receiver request records. Local self-cancellation shares its source absence node with its actual receiver request, counted once. Each node has bounded parent/request links; dependency inspection is at most retained node count. Existing roots still consume one reservation each. Incoming positive admission consumes no second source intent slot.

max_receipt_entries counts unique reserved plus retained records across sender completions, receiver admissions and applied retirement. First remote positive reserves one source positive ACK slot and one outbox; a local positive needs no transport receipt. Canceling a remote predecessor adds one source absence node, one anti outbox, one anti ACK slot and one applied-proof slot; its original positive ACK slot remains retained/reserved. Later remote N adds one positive intent, one blocked/ready positive outbox and one positive ACK slot. Receiver cancellation adds one request transition, one pending anti slot, one reserved tombstone, anti admission ACK plus applied-proof receipt slots, and one positive readback slot only if no positive record exists. Local self-cancellation shares one bounded constant-size receipt bundle containing the immutable queued-anti readback and eventual applied proof, requires no positive/anti transport ACK slots, queues one local anti and reserves one tombstone. The bundle materializes at cancellation publication and counts once as retained, not again as a reserved applied slot. Local application also completes its actual source dependency atomically; repeated public readback/ACK is idempotent.

At anti/rollback publication, preflight every induced descendant cancellation/output role, pending/history/tombstone totals, source intents/outboxes/completion slots, receiver canonical request/receipt reservations, checked incarnation/ID/validity/revision headroom. Reserved slots turn into records; completion never allocates unreserved headroom. Capacity failure cannot publish partial model/queue/allocator/anti/applied facts. Retained old positives and request/proof obligations remain bounded/accounted until exact completion/pruning.

Failure order: health/mode/horizon as applicable; canonical peer liveness/sealing; actual actor/configuration/ownership/authority; kind/identity/routes/ancestry/GVT; exact existing request/receipt validation and zero-allocation retry; cohort graph validation; source/incoming transition capacity; outbox; shared receipt; pending; history; tombstone; checked incarnation/ID/LP validity/own revision. Pre-callback checks use known actual demands; post-callback checks use staged actual batch deltas. Selected-LP compensation epoch and own revision headroom are mandatory pre-callback checks even though output destinations/capacities are unknowable then; the final checked-headroom position applies to actual post-callback deltas. Existing root scheduler validation/conflict precedence stays intact. Source transition corruption errors require private unit oracles, not public forging APIs.

## Complete native group cuts

Exclusively borrow every actual participant; reject duplicate runtime, incomplete/unexpected LP coverage, mismatched actual registered peer witness/configuration, unsealed/unhealthy/stale actor or open initial inputs before publication. Every participant must validate every other actual owner, including self; identical configured fresh issuer cannot replace the registered object. Validate nonregressing floor and minimum unresolved obligation for all participants, then every capacity/graph/epoch/revision precondition before touching any floor. Use existing GvtBeyondPending for an unresolved minimum below the proposed cut. A processed frontier or independent per-peer sample is not a proof.

Stage any required snapshot clone outside gates; publish all participant floors/accounting under one canonical set of gates, detach retired snapshots and release guards before Drop. Err means no floor/accounting publication, though callback panic can poison a participant; poisoned IDs report that accurately. Ok means every participant committed the common floor; cleanup_failures reports post-publication Snapshot Drop panic and poisoning without retracting the cut. Equal-floor retry is idempotent when no newly eligible pruning exists. One changed participant publication increments its revision once; advance its touched LP validity epochs once for floor/history/tombstone changes. Proof-only pruning changes accounting, not model validity.

Unresolved obligation cut bound is the MIN of every referenced event tick. Completed proof retention protects the MAX of every referenced envelope tick and every retained unresolved dependency. Example old30/new25 at cut26 must retain old30 tombstone/proof even if new25 is collected. Equality stays reversible. Lost ACK retains sender obligation and prevents corresponding receiver proof pruning. Common-cut pruning requires all protected envelopes strictly below the floor and no retained unresolved dependency; rewire bounded surviving parent links before dropping completed nodes, never leave a missing ancestor. Root reservations remain lifetime-retained. Late pre-GVT tickets, admissions, ACKs and retirement proofs reject before caches.
