## Cancellation without a successor

Example: source S's input emits ordinal0 to receiver A. A straggler causes rollback and replay emits no ordinal0. The retained original positive still needs an accounted anti, actual receiver cancellation and source completion. A request requiring both predecessor anti and successor envelope cannot express this valid rollback. Never manufacture a dummy successor, leave the old effect live, silently discard accounting, or reject valid reduced-output replay.

The next exact contract must define a privately minted cancellation-only transition, distinct from replacement with an actual successor. Its completion binds actual sender/receiver identity, predecessor envelope/anti, transition identity and recorded applied accounting. Positive/anti admission ACK is insufficient. Reserve eventual completion records before accepting work; exact retries are idempotent at full capacity. Applied cancellation means old local effects are removed or absent, a tombstone prevents late reapplication, and induced downstream antis are retained in real accounted state.

Later replay may reintroduce the same source/logical output cohort while an earlier cancellation is still pending. Source-side ancestry/dependency accounting must retain every unresolved predecessor and block the new positive until all required applied cancellations arrive. An intermediate superseded version never becomes ready, even briefly. Cancellation-only completion closes its exact obligations and must not release an unrelated/superseded successor or erase remaining ancestors. Exact public disposition, private transition identity, accessor/readback and error signatures remain to be jointly reviewed; optional-successor representation is a proposal, not a settled API.

## Every model callback is outside lifecycle locks

P::Snapshot::clone and snapshot Drop can execute user code, in addition to on_event, snapshot, restore and process destructors. Rollback clones historical snapshots; fossil collection, replacement and failure cleanup can destroy them. Holding peer read gates across any such operation can deadlock if model code drops a peer whose Drop needs its exclusive gate. Merely excluding on_event/restore is insufficient.

The exact implementation join must distinguish callback staging from publication. Preserve original input/queue/history/allocator/accounting until publication; collect the necessary snapshots and model/RNG state outside native lifecycle locks. Release all lifecycle guards before running model callbacks. Reacquire unique gates and revalidate live registered owners, complete metadata, capacities, epochs and accounting before publishing any outputs or transition. A peer dying during a callback requires faithful logical model/RNG restoration outside guards, while queue/history/outbox/emitter work remains unpublished. Restoration may invalidate model-owned handles: GenerationBitset::restore deliberately advances its nonrollback epoch even for identical logical bits. Never rewind validity epochs or claim all tokens unchanged after compensation. The next exact API must report compensated attempts and conservatively invalidate the affected runtime LP token using checked headroom reserved before callbacks; failed restore poisons. Cleanup/token invalidation after foreign-peer loss and its accounting-revision semantics still require exact review. Snapshot clones and all temporary/retired snapshot destruction on success/error branches occur outside guards. If callback stages cannot preserve this invariant, decompose or revise the design before source dispatch rather than weaken the unchanged-state oracle.

## Mandatory next joined evidence

The enabled-handler join must route actual local outputs once and remote outputs only into retained source outboxes; support valid stragglers, suffix replay, actual anti admission/application and predecessor barriers. It cannot enable ordinary handlers but reject valid rollback/reduced-output cases. Independently seeded model/RNG/trace comparison, mixed local/remote bounds failures, P-to-N1-to-N2 chains, cancellation-only/reintroduction, dropped peers inside snapshot clone/Drop/handler callbacks and exact duplicate retirement readback are required. Complete native group cuts, full CI/hosted normal merge and Track49 durable real process/rank evidence retain their later gates. No mirrored remote model or metadata-only proof substitutes for actual ownership/accounting.


## Qualified proposed transition representation

Propose opaque NativeTransitionId (actual source issuer plus checked local sequence), Clone/Debug/Eq/PartialEq, no public construction/deserialization/ordering. NativeRetirementDisposition is Copy/Debug/Eq/PartialEq with CancellationOnly and Replacement. A privately minted request and applied capability expose transition_id, predecessor_anti, successor()->Option<&OptimisticMessage>, disposition, actual sender and old_receiver; applied capability also exposes recorded_revision. Private construction enforces None exactly for CancellationOnly. acknowledge_native_retirement completes the exact retained transition and recomputes latest-positive readiness; an API named only for replacement release is insufficient for cancellation-only completion. Exact signatures and failures remain proposed.

For P-to-Absent-to-N, retain immutable P-to-Absent intent/request. N inherits every unresolved predecessor dependency; absence is a genuine intent node, not a synthetic delivery. Applied P cancellation satisfies only its exact known ancestor transition. Only the current latest positive with every ancestor complete can become ready; an absent/superseded intermediate node never does. Actual sender/receiver identity binding precedes cache lookup; applied capabilities bind the original complete request rather than whichever successor is latest when they arrive.

Every runtime-issued anti ticket privately binds its immutable retirement request. receive_native_retirement and anti admit_native must enter a canonical admission path: validate actual actors/request; reserve bounded records; queue the exact anti once. Request-first and anti-first share records. Receipt establishes queued/accounted state only. The budgeted anti step produces applied proof after effects are removed/absent, tombstone protection exists and induced descendant antis are retained in actual accounted state. Positive-never-arrived cancellation reserves eventual tombstoned readback before accepting work, preventing late-positive surprise allocation. A local self-transition unifies real source intent and receiver request instead of constructing a loopback mirror.

The transition bound counts source intent nodes, including first root/output versions and absence intents, plus incoming receiver request records; the cohort-head map indexes these records rather than adding an unbounded ledger. Reserve source anti/completion and receiver anti/applied-retirement/late-positive readback before cancellation. Local self-accounting may share one actual applied-proof record across roles. Exact per-role receipt counts, headroom and failure precedence need final freeze.

## Run-step and proof-retention boundaries

Atomicity is per step/selected round. A later failure cannot erase earlier committed steps in the same run call. The failure result must retain completed progress, consumed attempt budget, committed observer messages, pending counts, failure phase and compensated/invalidated LPs. Outboxes remain authoritative. Proposed owned behavior commits horizon and automatic initial-input closure with the first successful step; idle/budget-zero/failed-first-step calls leave them unchanged. Legacy behavior stays separate. These return types and revision/epoch semantics are not yet accepted.

Stable native admission capabilities record historical membership/revision. Original Pending readback after execution/tombstoning requires current retained exact accounting; it does not prove present pending state or applied retirement. Late pre-GVT ticket/cap rejection precedes cache readback.

An unresolved transition constrains a cut by the minimum referenced tick. Completed-proof retention instead protects all referenced envelopes: predecessor30 replaced by successor25 cannot lose old30 tombstone/receipt protection at cut26. Retain through the maximum referenced tick and unresolved descendant dependencies (or equivalent per-envelope records); equality remains reversible. Lost ACK retains source obligations. Complete-group collection exclusively borrows every actual healthy sealed participant with closed initial inputs; independently sampled or idle processed frontiers cannot supply the cut.

## Qualified proposed local compensation exception

After a staged callback fails publication because a foreign peer died, restore logical model/RNG state without any lifecycle guards. Then acquire only the actual local own gate to publish the pre-reserved validity epoch for each affected LP and one checked own accounting revision with an aborted-step observation. The exclusive runtime borrow prevents self-Drop during this operation. Foreign-peer death must not prevent this narrowly defined cleanup. It is not permission to bypass stale-peer checks for ordinary scheduling, admission, ACK, retirement or group cuts.

Emitter allocation, queues, history, outboxes, root/transition reservations and receipt obligations remain unpublished and unchanged. Cleanup issues no native send/admission/retirement fact and does not advance horizon or initial-input closure. The failure result reports invalidated LPs, consumed attempt budget and previously committed progress. Restore, snapshot clone/cleanup or local gate failure poisons the runtime; never claim unchanged validity after compensation. Retained/staged snapshot destruction happens only after the own guard is released. Qualified architecture accepts this as a proposed local compensation commit; exact API signatures, pre-reservation counts, panic handling and independent oracles still require review before dispatch.
