# Risk Register: Track 33 WebGPU Compute for Browser

Severity scale: Likelihood 1-5 x Impact 1-5. Low 1-4, Medium 5-9, High 10-16, Critical 17-25.

| Risk | Likelihood | Impact | Severity | Mitigation | Owner | Escalation trigger |
|---|---|---|---|---|---|---|
| Browser WebGPU availability — WebGPU is not yet enabled by default in all target browsers (Firefox, Safari); demo unreachable for most users | 5 | 4 | 20 | Build feature detection and graceful fallback to CPU Wasm into the demo page; target Chrome stable (has WebGPU) as primary, Edge and Firefox Nightly as secondary; document browser requirements prominently | webgpu-agent | WebGPU unavailable on Chrome stable for Windows/macOS/Linux |
| WGSL shader incompatibility — WebGPU WGSL subset differs from native WGSL; shaders that compile on wgpu fail in browser | 4 | 4 | 16 | Maintain a separate WebGPU WGSL shader directory; run the browser-GPU-free subset validator in `website/webgpu-demo`; add `naga` or headless Chrome shader compilation once dependencies/runners are available | webgpu-agent | WGSL shader fails the static validator or later fails to compile in Chrome with `--enable-unsafe-webgpu` |
| Wasm + WebGPU bridge overhead — copying data between Wasm linear memory and WebGPU buffers introduces latency that negates GPU speedup | 4 | 3 | 12 | Use zero-copy buffer sharing where the WebGPU spec allows (import Wasm memory as `GPUBuffer`); profile upload/download phases separately; if bridge overhead is >20% of total frame time, pivot to shared `ArrayBuffer` strategy | webgpu-agent | Bridge overhead exceeds 20% of frame time on reference hardware |
| WebGPU spec churn — the W3C WebGPU spec is still evolving; API changes break the `web-sys` bindings or WGSL shaders between Chrome versions | 4 | 3 | 12 | Pin `web-sys` to a known-good version of the WebGPU bindings; run the demo in Chrome Canary weekly to detect breakage early; maintain a compatibility table in `docs/gpu-compute/webgpu-wgsl-subset.md` | webgpu-agent | Demo fails on latest Chrome stable after a Chrome update |
| Browser GPU resource constraints — consumer GPUs have less VRAM than HPC GPUs; large simulations exhaust browser GPU memory and crash the tab | 3 | 4 | 12 | Cap agent count per GPU tier; implement progressive agent count scaling with VRAM detection; display memory warnings in demo UI before launching the simulation | webgpu-agent | Demo crashes on a GPU with 4 GB VRAM at any agent count advertised in the UI |
| Firefox and Safari WebGPU support is gated behind flags indefinitely | 3 | 3 | 9 | Treat Chrome as the primary supported browser; test on Firefox Nightly to track progress; document that Firefox and Safari require flags and are not supported for release | webgpu-agent | Firefox removes WebGPU from Nightly or delays stable release beyond 2026 |
| Headless CI testing requires Chrome flags (`--enable-unsafe-webgpu`) that may not be available on all CI runners | 3 | 3 | 9 | Test CI headless Chrome with WebGPU flag availability; if unavailable, run WebGPU-specific gates on a self-hosted runner with GPU; CPU-only gates run on standard CI | webgpu-agent | Headless Chrome with WebGPU flag fails to launch on CI |
