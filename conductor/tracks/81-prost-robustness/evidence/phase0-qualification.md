# Phase 0 Qualification: Prost Distributed Envelope Encoding

**Track:** 81 (`81-prost-robustness`)  
**Dependency Qualified:** `prost = { version = "0.13.5", default-features = false, features = ["std", "prost-derive"] }`  
**Decision:** **ADOPT (GO)**  
**Date:** 2026-10-25  

---

## 1. Context and Problem Statement

The optimistic distributed simulation subsystem in `crates/kairo-ecs-grpc` requires wire-level serialization for `KairoOptimisticEnvelopeV1`, which carries causal ancestry frames, logical process identity, 128-bit timestamps, 128-bit simulation namespaces, authority epochs, and event payloads across network boundaries.

Prior to Track 81:
1. `crates/kairo-ecs-grpc/src/envelope.rs` implemented a custom, ad-hoc, big-endian binary byte-packing codec (~264 lines of manual pointer arithmetic and buffer manipulation).
2. The ad-hoc format lacked language-neutral interoperability with standard Protocol Buffers runtimes (e.g., Python, C++, Go, or standard gRPC endpoints).
3. The custom format could not be easily validated by standard schema linters or deserialized by external distributed participants without maintaining duplicate manual parsers.

`simulation.proto` already exists in `crates/kairo-ecs-grpc/proto/` describing runtime transport contracts, but the optimistic envelope codec remained hand-rolled.

## 3. Security and Robustness Contracts

1. **Structured Protobuf Serialization:** Uses standard Protocol Buffers wire encoding generated by `prost-derive`.
2. **Deterministic Full-Range Preservation:**
   - 128-bit `tick`: serialized via 16 big-endian raw bytes or fixed byte slice, preventing 64-bit truncation or overflow.
   - 128-bit `simulation_namespace`: serialized via 16 big-endian raw bytes, preserving full UUID/domain fidelity.
3. **Envelope and Payload Size Caps:**
   - Maximum encoded envelope size: `MAX_ENCODED_ENVELOPE_BYTES = 65_536` (pre-flight and post-encode check).
   - Maximum payload size: `MAX_PAYLOAD_BYTES = 4_096`.
   - Maximum ancestry depth: `MAX_ANCESTRY_DEPTH = 128`.
   - Maximum ancestry nodes: `MAX_ANCESTRY_NODES = 129`.
4. **Rejection Oracles Maintained:**
   - R01: `UnsupportedEnvelopeVersion`
   - R02: `ProtocolIdMismatch`
   - R03: `ProtocolVersionMismatch`
   - R04: `EnvelopeTooLarge`
   - R07: `AuthorityModeMismatch`
   - R13: `AncestryDepthExceeded`
   - R14: `RootSourceMismatch`
   - R15: `OutputTickNotStrictlyFuture`
   - `MalformedFraming` for corrupted or truncated protobuf buffers.

## 4. Frozen Budgets

- **Max Encoded Envelope Byte Size:** 65,536 bytes (64 KB).
- **Max Event Payload Size:** 4,096 bytes.
- **Max Ancestry Chain Depth:** 128 output frames (129 total nodes).
- **Roundtrip Codec Latency:** < 50 µs for standard root and 2-frame envelopes.
- **Transitive Crate Budget:** Pure Rust; 0 native C runtime dependencies.
