# Risk Register: Track 38 FMI/FMU & Digital Twin Bridge

| Risk | L | I | Sev | Mitigation | Owner | Escalation trigger |
|---|---|---|---|---|---|---|
| FMI standard version fragmentation: tools support different FMI versions (2.0 vs 3.0) | 4 | 4 | 16 | Support both FMI 2.0 and FMI 3.0 import; document per-tool compatibility matrix; provide FMU version detection at load time | fmi-agent | Tool vendor drops FMI 2.0 support without migration path |
| FMU binary incompatibility across operating systems | 4 | 4 | 16 | CI matrix tests FMU import on Linux (glibc/musl), macOS (x86_64/arm64), Windows (MSVC); document platform-specific FMU requirements; provide cross-compilation guide for FMU export | fmi-agent | FMU fails to load on a supported target platform |
| Co-simulation step size negotiation between master (KairoECS) and slave (FMU) diverges | 3 | 5 | 15 | Implement step size negotiation per FMI 2.0 Section 4.2.3; reject FMUs that require step sizes outside KairoECS tick configuration; document recommended tick-to-FMU-step mapping | fmi-agent | FMU rejects proposed step size and no fallback resolution exists |
| AAS schema evolution breaks JSON connector validation | 3 | 4 | 12 | Pin AAS schema version in CI validation; version AAS output with schema version tag; subscribe to AAS specification change notifications | fmi-agent | AASX Package Explorer rejects generated descriptor |
| Digital twin stale-state risk: physical asset and virtual model diverge | 4 | 4 | 16 | Implement TwinStateDiff with checksums and timestamp-based drift detection; require heartbeat from live data connector; alert on synchronization gap exceeding configured threshold | fmi-agent | State drift exceeds max_staleness_seconds without alert |
| FMU import crashes KairoECS process due to buggy third-party FMU | 3 | 5 | 15 | Run FMU import in a subprocess with IPC (shared memory or socket); implement watchdog timer that kills runaway FMU steps; provide sandbox mode for untrusted FMUs | fmi-agent | FMU import causes SIGSEGV or hangs simulation loop |
| FMU export binary not reproducible: build non-determinism | 3 | 4 | 12 | Pin toolchain versions in CI; use deterministic compilation flags; verify FMU binary hash across independent builds; document build environment requirements | fmi-agent | FMU binary hash differs between CI and developer builds |
| FMI 3.0 scheduled execution and clocks semantics misimplemented | 3 | 3 | 9 | Defer FMI 3.0 clock support to post-v1.0; document limitation clearly; reject FMUs that require clock support with explicit error | fmi-agent | User attempts to import clock-dependent FMU without documented limitation |
| Digital twin connector floods streaming pipeline with high-frequency variable changes | 3 | 3 | 9 | Implement change-detection publishing (publish only on delta > epsilon); configurable sample rate and batch window; backpressure from streaming pipeline must throttle FMU stepping | fmi-agent | Streaming pipeline buffer exceeds configured limit |
| OpenModelica round-trip test produces diverging trajectories | 3 | 5 | 15 | Investigate root cause: numerical solver differences, FMU variable mapping errors, initialization semantics; document tolerance expectations per model class; add trajectory comparison tool | fmi-agent | OpenModelica trajectory differs from native beyond configured tolerance |
| Track 38 workspace wiring regresses and CI stops checking `kairo-ecs-fmi` | 2 | 3 | 6 | Keep `crates/kairo-ecs-fmi` in root `Cargo.toml`; validate with `cargo metadata --no-deps` and `cargo check --workspace` | fmi-agent | CI or local metadata no longer lists `crates/kairo-ecs-fmi` as a workspace member |
| Archive extraction and dynamic symbol loading need dependency-policy approval | 3 | 4 | 12 | Keep unpacked-FMU validation and raw ABI wrappers dependency-free; add `zip` and `libloading` only after approval and supply-chain review | fmi-agent | FMU import is claimed complete without loading symbols from a real `.fmu` |
