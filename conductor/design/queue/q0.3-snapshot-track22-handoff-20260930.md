# Q0.3 snapshot and Track 22 handoff

**Status:** Handoff for owner decisions; no portable checkpoint contract is adopted; a portable checkpoint contract is not available.

## Current surfaces

`kairo_ecs_state::WorldSnapshot` is a live in-memory view produced by `World::snapshot()`. It contains the sorted live entity IDs (index and generation) only. It is not a serialization format and does not capture component values, allocator/free-list state, queue state, or scheduler state. The visualization crate can consume it as a view of the current world; that use does not provide capture/restore.

Track 22's current `checkpoint --output` command writes a scaffold manifest containing a schema label, a last-completed-tick value (or `unknown`), and `interrupted` status. `resume --checkpoint ... --output ...` checks that the manifest path exists and writes a scaffold resume request. The documented `run`, `checkpoint`, and `resume` handoff is for wrapper compatibility. Track 22 explicitly leaves real execution and checkpoint/resume semantics as follow-up work. These files and commands do not establish a portable checkpoint contract, restoration behavior, or resumability evidence. No queue-owned codec or schema is proposed here.

## Future Track 22 coordination

A future portable contract needs owner agreement on at least world generations and allocator state, component values and their encodings, queue/admission contents and ordering, leases and revisions, pending work and scheduler ordering/state, and RNG/seed state and continuation rules. These are handoff topics only; this note selects no representation or semantics.

The local Flow event-kind allocation is recorded in [the Kairos core contract](../../contracts/core-contract.md); it remains FlowRuntime-local. The lifecycle sidecar is a separate proposal in [Q0.3 resource lifecycle sidecar](q0.3-resource-lifecycle-sidecar-proposal-20260930.md). Neither document is a checkpoint format or substitutes for Track 22's contract.

## Link and owner review

The referenced Kairos contract and sidecar paths above were checked and resolve. The sidecar proposal has no embedded Markdown links to repair. No broken or stale link was verified in the reviewed sidecar note; this handoff therefore makes no link edit outside this owned output.

Owner decisions remain pending: Track 22 owns checkpoint and resume orchestration; Track 01 owns scheduler/RNG changes; Track 03 owns queue/runtime semantics; Track 04 owns lifecycle schema and encoding; Track 25 reviews public API/version policy. The accepted local Flow event allocation and proposed lifecycle sidecar do not close these decisions.
