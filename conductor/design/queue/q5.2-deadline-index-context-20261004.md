`ClaimQueue` stays public and unchanged. It stores waiting `PriorityKey`s ordered
by priority, enqueue sequence, and request ID. Current timeout handling scans
staged queues and processes resources in ResourceId order, then keys in
PriorityKey order. A deadline-first index must query only its inclusive due
prefix and sort those due records by PriorityKey per resource to preserve this
observable order. Submit immediately times out already-due work. Grant clears
the deadline; preemption/requeue must not restore it. Despawn removes waiting
ownership but preserves the terminal request's deadline field. Queued Cancel
clears it; Reprioritize keeps the deadline while replacing the key.

## Reuse and integrity boundary

Add private per-resource `WaitingDeadlineIndex { entries: BTreeSet<(SimTime,
PriorityKey)>, expected_len: usize }`. Stage only existing causal resources,
alongside `QueueDelta` from `queue_delta.rs`; absent resource IDs continue to
skip staging. Missing components or inconsistent witnesses are `InvalidState`
before scheduler consumption. Require staged cardinality to equal the old
witness and not exceed primary queue length; carry old expected count for group
preflight and new staged count for apply. Validate due and explicitly touched
entries against request existence, resource, queued state, exact deadline,
derived key, primary membership, and witness. `Deadline(id)` must validate its
tuple even when the deadline is future, or stale future tuples escape the
due-prefix check. Touched Active/Suspended requests with `Some(deadline)` are
invalid. Pending may retain a deadline but is not indexed. Terminal requests
may retain deadline after Despawn; do not reject that field, but never index a
terminal request. Preserve terminal/invalid-lease ordinary error order and
make no claim about an unvisited causal tail. The witness detects unpaired
count drift; do not claim untouched global integrity if set and witness were
consistently corrupted. Do not scan all requests, resources, or index entries.

Preflight both primary and deadline `QueueChanges` before plan export and
group-wide at commit before factories/writes. Include index snapshots in the
same rollback boundaries as queue snapshots: ordinary command rejection keeps
independent due-boundary effects; structural `InvalidState`/`CounterOverflow`
rejects the whole plan. Cleanup creates/removes the index with resource
lifecycle. Maintain it for queued deadline Submit, due timeout, queued Cancel,
Despawn, Reprioritize, and grant; pending Cancel is not indexed. On resource
removal, after the existing ordinary `ResourceInUse` check, require the primary
queue and deadline index to be consistently empty before deleting either
component. Structural failure must preserve group atomicity.

## Required focused checks

Cover absent/wrong due and touched entries, count mismatch/cardinality bound,
missing component, future `Deadline(id)` validation, Pending metadata, touched
Active/Suspended invalid metadata, and Terminal metadata/index rules; inclusive
exact-deadline behavior; ResourceId then PriorityKey ordering (including
different deadlines); cancellation and Despawn; grant followed by preemption
without deadline restoration; consistent empty-resource cleanup; and
multi-resource failure atomicity. Retain existing deadline/rollback oracles,
including `deadline_expires_before_release_in_both_insertion_orders`,
`rejected_release_preserves_due_completion_and_replacement_boundary`, and
`despawn_rolls_back_earlier_resource_when_later_waiting_key_is_corrupt`.
