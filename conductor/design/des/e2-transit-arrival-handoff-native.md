# Native transit arrival handoff

`TransitContext::new_handoff` routes an existing pending service `WorkId` through a real `FlowRuntime` without creating a resource request at transit start. The same work remains pending until a caller chooses real service capacity and submits it after arrival.

The arrival witness records the actual accepted Flow delivery event and tick. Both final Domain progress and Resume at a completed route frontier can commit the witness through the normal domain-plan receipt path. Handoff arrival emits no Acquire or follow-up command; an accepted empty callback batch is sufficient. Pause at the route frontier stays paused until Resume. A rejected or budget-halted candidate does not publish an arrival witness.

`observe_transit_arrival_handoff` checks a dispatch against the authoritative typed context. It validates the carrier's public actor-domain mapping, runtime identity, and any carrier ID already bound by start. A matching event with a different tick, an error, or a rejected/non-empty callback batch fails with `FlowError::InvalidWork`; an unrelated event returns `None`. `pending_transit_arrival_handoff` returns `None` before an arrival witness exists and exposes the committed witness while the service `WorkSpec` has no request. After successful service submission binds the same work to a request, both observer and pending accessors return `None`, including after grant and completion. The receipt has no public constructor. Because `FlowDispatch` is constructible, this check is structural consistency with the committed context, not cryptographic dispatch authenticity. The context also retains whether the witness came from Domain progress or Resume; current `FlowDispatch` exposes no cause field, so that private cause is provenance only.

The constructor verifies that the service work is currently present and pending. Flow maintains owner liveness by removing every work row whose `WorkSpec.owner` is despawned, then removing its `WorkSpec` and progress state in the same accepted transition (`crates/kairo-ecs-des/src/flow.rs`, `removed_works` collection and cleanup). Thus a retained `WorkId` whose owner has been despawned fails the public `flow.work` lookup used by `new_handoff`; this relies on Flow's existing lifecycle invariant rather than adding an ABM-only actor registry check.

Legacy `TransitContext::new` keeps its timed Acquire behavior. The v1 checkpoint DTO, KTCXCPV1 bytes, and version-1 codec remain unchanged. Direct native and byte capture of a Handoff context returns the existing `TransitContextCheckpointError::InvalidState` before route encoding. Flow checkpoint capture reaches the registered opaque context encoder before that ABM guard can reject the payload. V2 serialization, restore, and persistence qualification are outside this native feature.
