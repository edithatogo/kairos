# C4.1 invalid inputs and runtime gate clarification v1

This reviewed test-only addendum overrides earlier ambiguous invalid-input
counting. Production schemas and C0.2 definitions stay intact.

- Whole-input invalid comparisons use zero reference/candidate metric counts:
  no empirical population was used. Retain raw nonnull attempted supports in
  diagnostic.attempted_support_counts. Primary rejected_input accounts for
  nonnull rejected supports; primary observed is zero, nulls are missing.
  rejected_input is a fixture reconciliation bin, not a public metric column.
  Valid cases retain rejected_input=0; primary bins sum to eligible, and
  eligible+excluded=cohort_total. No invalid support is a valid observation.
- Comparator mocks are accepted only as comparator self-tests. The opt-in
  C4.2 gate requires provenance.kind=runtime_candidate, exact 40-hex producer
  commit and nonempty producer_api binding before comparing metric results.
  Metadata alone does not authenticate a runtime: C4.2 review must independently
  verify the named producer/source and execution receipts. A mock passing the
  generic comparator is never a runtime gate pass.
- Equivalent minute/second populations require a matched fixture pair with
  W1 scaling by 60 and identical KS_D, independently recomputed.

C4.1 fixture preparation only; no C4.2 implementation or C-04 acceptance.
