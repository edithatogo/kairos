# C1.3 ingestion implementation contract v1

Coordinator reviewed 2026-10-04 for the user-authorized C1.3 implementation.
Owners 21 semantics, 04 transport, 12 conformance. Private experimental Rust
implementation; no new public API, scheduler, manifest/CLI, dependency or schema
change. The existing C0 logical records and physical v2 remain authoritative.

## Normalization

Freeze one c11.synthetic-map-v1 request envelope with rows empty. Consume bounded
row chunks through the existing occurrence/recording/message/knowledge mapper and
checked UTC origin conversion. Chunk rows/serialized bytes and total identities
have explicit nonzero caps. Preserve all clock lineage, raw precision, exclusions,
outcomes and diagnostics. Reject envelope changes and dataset-wide duplicate
source-event keys, including keys in excluded candidates. Long unrecognized kinds
must fail, not vanish. Occurrence/rank/key/source_order validations stay unchanged.
Dataset outcome identities are (case,endpoint); duplicates fail rather than
double-counting. Outcomes are separate from event-candidate accounting.

`ingestion_normalize` provides private `Normalizer::new(template, Limits)`,
`push(rows)->MappedChunk`, cumulative `Counts`, `mapping_hash`, and `order_key`.
Limits fields: max_chunk_rows, max_chunk_bytes, max_identities (usize).
Counts fields: source_rows, candidate_units, accepted_units, excluded_units,
failed_units, unresolved_units, cohort_denominator, missing_triage (u64).
MappedChunk fields: events, exclusions, outcomes, diagnostics (Vec<Value>).
Counts must reconcile candidate partition exactly with checked addition.
`order_key(&Value)->Result<TraceOrderKeyV1,String>` enforces C0's exact six-field
tuple with arbitrary decimal rank, bytewise strings and integer ticks. Input
identities stay local; public evidence contains synthetic fixtures only.

## Sorting

`ingestion_sort::external_sort` consumes `Iterator<Item=Result<Value,String>>`,
scratch directory, SortLimits { max_run_rows, max_run_bytes, max_record_bytes,
merge_fan_in }, and a fallible record sink. All limits nonzero, fan-in >=2.
Each record is validated with order_key before serialization. Bounded sorted
runs are exclusively created inside a new private workspace; multilevel merge
opens at most fan-in inputs and keeps one bounded record per input. Records are
serde_json's deterministic BTree-map compact JSON plus LF, version
`serde-json-btree-ndjson-v1`; this is byte identity, not RFC8785. No f64 sort.
Reject oversized records, invalid keys, IO/corrupt runs and sink errors. Cleanup
only files created by this invocation on success/error; never replace/delete
unrelated scratch contents. Return row/run/merge-pass counts. Equal key records
retain insertion order, although dataset identity validation forbids ambiguity.

## Semantic validation

`ingestion_validate` consumes sorted C0 events with explicit ValidationPolicy.
Declared precedence edges must be acyclic and reference declared event kinds.
For each case/occurrence, required event anchors, paired start/end kinds and
edge timestamps validate without fabricating precision; equal ticks permitted.
Source-recording order does not dictate occurrence order. Maintain explicitly
bounded case/identity state; failure to fit bounds is an error, not eviction.

Occupancy is declared by enter/exit event pairs for resource+location+case+
occurrence, supplied positive capacities and exact half-open [enter,exit)
intervals. Assignment or administrative episode end never implies occupancy.
Missing/open/reversed intervals and absent resource/location/capacity remain
explicit diagnostics, not fabricated endpoints. Releases precede admissions at
equal ticks. Resource-feasible strict mode rejects overcapacity; exploratory
mode reports infeasibility without claiming feasible replay. Strict invalid
chronology/required anchors fail; exclusion mode quarantines complete affected
cases with reasons, retaining the original local records. Observation window
bounds are explicit, and out-of-window events are censored/quarantined, not zeroed.
Private interface signatures may be settled by its packet after sort acceptance;
no domain assumptions or silent repairs are permitted.

## Provenance and integration

Coordinator joins actual normalized records, external sorting, semantic validation
and sink output. Manifest records version, dataset/mapping IDs, envelope digest,
explicit input hashes, origin/time resolution/rounding, ordering/version, source
rows and candidate partition, outcomes/censor status, validation exclusions by
reason, emitted populations/counts/hashes, bounds and resource-feasibility status.
Reject count inconsistency and missing required input evidence. Private source
records/exclusions never enter the public manifest. Changing physical chunk/run
or row-group sizes or order (stable source keys/order) preserves record hashes.
Actual Arrow IPC/Parquet adapter conformance remains necessary: NDJSON alone is
not transport proof. No clinical validation, stable public API or C1.4 claim.
