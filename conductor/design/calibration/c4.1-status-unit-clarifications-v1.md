# C4.1 status and unit clarification v1

Reviewed integration input to the frozen fixture contract. This resolves its
empty-population vocabulary against C0.2 without changing public sidecars.

- Fixture status vocabulary is ok, empty, insufficient_data, invalid. Both
  populations with zero valid point values use empty; only one empty population
  uses insufficient_data. All non-ok metrics are null. Fixture ok maps to C0.2
  computed when a future qualified sidecar adapter is implemented. This test
  protocol is not calibration_metric.v1 serialization.
- reference/candidate counts are valid point observations, including zero-weight
  observations, excluding nulls. Null input instances are primary missing. Raw
  input lengths may be retained separately, never masquerading as point counts.
- Ordinary reference/candidate supports are already expressed in declared unit.
  Equivalent minute/second cases multiply supports and W1 by 60 while KS stays
  invariant. scale_ticks is fixed ticks per output unit, not a fitted parameter.
- Explicit origin cases represent unsigned u128 ticks. Subtract ONE common exact
  origin before conversion, validate exact offsets, then divide exact offsets by
  positive scale_ticks for output-unit supports. A scaled-origin case must prove
  this conversion. Fractional/signed supports remain rational unit values.
- Candidate provenance.algorithm_versions is the exact sorted unique set of
  versions used by fixtures in both Python and Rust comparators. Mocks identify
  kind=comparator_mock; no mock establishes C4.2 runtime qualification.
- Valid weighted W1 receives a separate SciPy crosscheck; weighted KS remains
  exact descriptive CDF reference only. Numerical crosschecks enforce the frozen
  tolerance and never retain p-values.

Earlier frozen source hashes remain auditable; this additive correction is bound
separately during integration. C4.2 through C4.4 and C-04 remain open.
