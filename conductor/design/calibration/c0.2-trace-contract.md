# Calibration trace, time, and mapping contract v1

Date: 2026-10-01. Status: C0.2 trace/time/mapping proposal for owner review;
not a runtime implementation, local-source mapping, or conformance claim. This
file narrows the C0.2 record contract to the trace boundary. The [placement
ADR](ADR-0005-calibration-placement.md), [adapter proposal](calibration-adapter-v1.md),
[Arrow schema contract](../../contracts/arrow-schema-contract.md), and
[VVUQ contract](../../contracts/vvuq-contract.md) remain controlling at their
respective ownership boundaries. Parent-project schema and orchestration
artifacts define corresponding cross-project records; this document does not
modify or replace those files.

## Scope and ownership

Track 21 owns normalized semantic records and mapping obligations. Track 04 owns
physical Arrow fields and IPC/Parquet encoding. Track 01 owns scheduler ticks,
core event order, identities, and any seed derivation. A future ED adapter owns
site dictionaries, source extraction, local privacy controls, and evidence of
local mapping/conformance. No code, public Rust API, Arrow implementation,
clinical rule, or source availability is established here.

The normalized record is `record_type=trace_event.v1` in schema family
`schema_version=calibration-v1`; it is distinct from legacy
`kairo_ecs.event_log.v1`. It must not alter legacy event-log meaning or claim
compatibility with its smoke serialization. Unknown schema versions fail closed
in the future opt-in calibration path.

## Canonical event identity and clocks

A trace event carries:

| Field | Contract |
|---|---|
| `record_type` / `schema_version` | Exact values `trace_event.v1` and `calibration-v1`. |
| `dataset_id` / `mapping_version` | Stable dataset and versioned mapping-bundle references. |
| `case_key` | Pseudonymous case grouping key, unique within the dataset mapping domain; never a seed or direct identifier. |
| `source_event_key` | Stable source-event identity, unique within a dataset. Preserve the original source reference only under the local controlled-provenance policy. |
| `occurrence` | UInt32 occurrence index; preserve the source value where supplied, otherwise assign only by a versioned deterministic rule. |
| `event_kind` | Controlled versioned kind. Keep the original source code/value in `raw_event` and mapping status in the mapping bundle. `episode_end` and `physical_departure` are distinct kinds and neither implies the other. |
| `occurrence_time` | Required event-occurrence instant with raw timestamp, declared source precision, source offset/zone, canonical relative tick, and lineage. |
| `source_recorded_time` | Nullable source-recorded instant. It is not replaced by resource update time. |
| `message_created_time` | Nullable source-message creation instant; distinct from event occurrence and record time. |
| `source_order` | UInt64 source row/sequence tie-breaker retained for audit; it cannot replace a missing stable event identity. |
| `resource_key`, `actor_key`, `location_key` | Nullable pseudonymous/local references; no raw person, MRN, or uncontrolled source identifier is allowed in a portable trace. |
| `disposition` | One of `provisional`, `realized`, or `unknown`; unknown is never promoted to realized. Preserve any source disposition code in `raw_event`. |
| `knowledge_availability` | Status (`known`, `not_yet_known`, `unknown`) plus nullable `available_at` time value. Its clock role and lineage are explicit, and it is separate from event time. |
| `raw_event` | Retain `source_family`, `source_event_type`, nullable controlled `source_record_id`, and source fields under the local data policy. |
| `quality_flags` | Versioned flags/reasons for missing, ambiguous, unmapped, deduplicated, or otherwise qualified fields. |

Each dataset manifest and mapping bundle declare the same explicit UTC
`origin_utc` and fixed `tick_resolution=1ns`. Convert explicit-offset timestamps
to UTC before checked subtraction from the origin. Each clock has its own raw input, declared
precision, source offset/zone, clock role, and lineage (`observed`, `derived`,
`defaulted`, or `unknown`). A nullable value stays null and has an explicit
reason/status; a clock with a different role must never be substituted.

Canonical relative time is a nonnegative unsigned 128-bit integer count of
nanoseconds from origin. The trace event `relative_ticks` equals the
`occurrence_time.relative_ticks` value. The eventual Arrow representation is
16-byte little-endian fixed-size binary; canonical JSON uses an unsigned decimal
string.
These are serialization requirements for the parent contract; Track 04 must
review and implement the physical Arrow mapping. Preserve source precision (for
example, minute precision remains minute precision); do not manufacture seconds
or finer precision. Reject timestamps before origin, integer overflow,
sub-nanosecond values that cannot be represented, and naive local wall time
until an explicit IANA-zone adapter defines DST fold/gap handling. Do not silently
truncate or round observed timestamps. If a separately reviewed ingestion
profile ever permits rounding, it must name the policy/version and count every
rounded value. The ADR-0004 sampled-duration ceiling rule does not authorize
rounding source observations. A date-only or otherwise coarse value is not an
instant: preserve its raw text and precision in `trace_exclusion.v1` with the
typed reason `date_only_or_coarse_precision`; do not assign midnight, an
interval midpoint, or a fabricated point tick. The same exclusion record keeps
raw event fields, raw time values, lineage, and an explicit reason for missing
timezone, DST ambiguity/gap, pre-origin, sub-nanosecond, overflow, missing
required time, or invalid mapping. Excluded records remain counted and cannot
enter normalized point-time ordering until a valid source-defined instant is
established.

## Stable ordering and event/interval semantics

For normalized trace presentation and deterministic processing, sort by:

```text
(relative_ticks, case_key, occurrence, event_kind_rank,
 source_event_key, source_order)
```

The versioned mapping bundle supplies a unique rank for every event kind in the
batch, with no rank ties. The source event key is required for input/file/chunk-order
invariance; `source_order` is the final source tie-breaker, not a substitute for a
stable key. `source_event_key` is unique within a dataset; reject duplicates.
Any source-level deduplication must be separately versioned and preserve all
candidate inputs and the selected outcome. `occurrence` is retained for source occurrence
semantics and participates in ordering.
This presentation order does not change core's `(time_ticks, priority,
sequence)` scheduler order.

A `location_interval.v1` is derived separately from the raw trace and retains
start/end event references, start/end times, location key, derivation/source
lineage, and interval status. An absent end means open or unknown, not zero
length. Reversed intervals are invalid; equal endpoints are retained only when
the named source semantics permit them. A location change proves physical
movement only when the local dictionary and boundary rule have been verified.
Episode end and physical departure remain independently nullable, separately
sourced, and separately counted.

## Report 30 provisional field references

The Report 30 field IDs below are external provisional references only. They
are not canonical trace IDs, case keys, event keys, or proof that a local field
exists. The supplied research set did not include its downloadable detailed
crosswalk or a local source extract. Every row therefore has local availability
`unknown`; the candidate standard semantics below must not be interpreted as
local implementation or conformance. Standard editions are the Report 30
research baseline only: FHIR R4 4.0.1, AU Base 6.0.0, AU Core 2.0.0, HL7 v2.5.1,
NAPEDC 2026–27, and OMOP 5.5.

| Provisional reference | Concept | Candidate standard semantics / limit | Local availability |
|---|---|---|---|
| `C0-F001` | `episode_id` | Candidate episode-grouping key. The supplied temporal subset establishes no canonical source mapping. | unknown |
| `C0-F002` | `subject_id` | Candidate subject reference; may map to `case_key` only through a separately evidenced pseudonymization rule. | unknown |
| `C0-F003` | `event_type` | Candidate controlled event vocabulary; retain original code and apply a versioned source profile. | unknown |
| `C0-F004` | `source_event_time` | FHIR partial through event-specific periods; HL7 EVN-6 exact when applicable and populated; AIHW partial milestone date/time; OMOP partial visit or detail bounds. | unknown |
| `C0-F005` | `recorded_time` | FHIR partial through `AuditEvent.recorded`, not `meta.lastUpdated`; HL7 EVN-2 exact when applicable; no generic equivalent in the audited AIHW/OMOP subset. | unknown |
| `C0-F006` | `location_id` | FHIR `Encounter.location.location` exact at the named standard-semantic level; HL7 PV1-3 partial pending local PL dictionary; AIHW establishment-level partial; OMOP `care_site_id` coarse/ETL-defined partial. | unknown |
| `C0-F007` | `location_start_time` | FHIR `Encounter.location.period` exact only where physical granularity applies; HL7 reconstructed partial after verified movements; AIHW internal ED location unavailable in the audited subset; OMOP `VISIT_DETAIL` partial only if the ETL supports it. | unknown |
| `C0-F008` | `location_end_time` | Same source and boundary limits as `C0-F007`; preserve a null/open interval rather than inventing an endpoint. | unknown |
| `C0-F009` | `episode_end_time` | FHIR partial; HL7 A03/PV1-45 partial with workflow interpretation; AIHW METEOR 799780/799782 exact; OMOP visit end partial. | unknown |
| `C0-F010` | `physical_departure_time` | FHIR final applicable location period partial subject to boundary; HL7 movement/end partial subject to boundary; AIHW METEOR 799756/799758 exact; OMOP partial and unsafe without ETL lineage. | unknown |
| `C0-F011` | `source_record_id` | Candidate source-row reference; retain only in locally controlled provenance and never publish as an identity. | unknown |

The `exact`, `partial`, and unavailable descriptions characterize candidate
semantics in a named standard only. Preserve standard edition, source code,
field-level mapping status (`exact`, `partial`, `unverified`, `unavailable`),
evidence reference, and local-availability status as separate values. Keep
source-local availability `unknown` until an authorized local extract and its
lineage have been inspected; an absent crosswalk is not evidence of an absent
field or feed.

Specific interpretation limits: HL7 MSH-7 is message creation time, not event
occurrence or source recording. A08 does not prove physical movement, and A03
does not always prove physical departure. FHIR `meta.lastUpdated` is a resource
version update, not event recording. AIHW episode end and physical departure
are separate concepts. OMOP visit end is not observed physical departure
without ETL lineage. Never infer an ED episode endpoint from a generic resource
status or location assignment alone.

## Review and implementation gates

Track 04 reviews/implements the Arrow representation and round-trip conformance;
Track 01 reviews time/order identity boundary where shared engine primitives
are implicated; Track 21 owns semantic validation and future executable mapping
rules; the domain adapter supplies site dictionaries and authorized local-source
evidence. The exact seed-purpose derivation remains a separate Track 01-owned
contract and is not defined by this trace document. No source feed, FHIR/HL7/
AIHW/OMOP conformance, timezone policy, or clinical endpoint is accepted here.
