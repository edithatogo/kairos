# C0.3 synthetic calibration oracles and evaluation protocol

**Status:** Coordinator proposal, ready for owner review. This freezes synthetic
mechanics oracles and the order of evaluation for C0.3. It does not establish an
ED clinical acceptance threshold, local parameter distribution, or runtime result.
No held-out ED data were read or used.

## Scope and decision boundary

C0.2 fixes the record semantics and deterministic W1/KS-D definitions. The
C0.3.sources ledger establishes that available values mix observed task means,
elicited choices, aggregate occupancy outcomes, and synthetic examples; local
ED feed access and several original research artifacts remain unavailable.
Therefore this proposal uses synthetic fixtures to test identifiability, leakage,
censoring, metric arithmetic and pipeline discipline. Synthetic values are not
prior evidence about an ED and must never become parameter defaults by promotion.

This proposal distinguishes three tolerance classes:

1. **Exact semantic oracles:** IDs, partitions, event/censor states, selected
   candidate and integer-tick residuals must match exactly.
2. **Numerical implementation tolerances:** tolerances for floating W1/objective
   output are fixed against an exact rational oracle and declared scale below.
3. **Empirical adequacy thresholds:** no universal acceptable ED discrepancy is
   set here. Those require the intended decision/use, stakeholder loss, supported
   local evidence and owner approval before opening the locked test set.

## Synthetic fixture suite

All times below are integer ticks at one declared synthetic scale; fixtures must
also run after exact unit scaling. Every generated row carries an explicit
synthetic provenance label and stable case/task/replication identity.

| Fixture | Construction | Hand oracle / required disposition |
|---|---|---|
| `OR-01-identifiable-service` | One resource; deterministic arrivals at ticks 0, 10, 20; known service duration 4 ticks; one observed task-start and completion per case; candidate grid `{3,4,5}`. No censoring, ties in endpoints, or latent route component. | Candidate 4 is uniquely recovered; alternatives produce nonzero exact residuals. Integer event order and candidate ranking exact. |
| `OR-02-confounded-sum` | Observed total interval 5 ticks with latent walking and task components; grid pairs `(1,4)`, `(2,3)`, `(3,2)` all imply total 5; no independent component observation. | Report the ridge/equivalence set; do not return unique walking/task estimates or treat tie-break selection as identification. Only sum=5 is identified. |
| `OR-03-identifiable-with-independent-anchor` | Same as OR-02 plus independently observed walking interval 2 ticks, source role explicitly primitive and available before prediction. | Unique pair `(2,3)`; reject if anchor is future/outcome-derived or not in the declared training window. |
| `OR-04-right-censoring` | Exponential clock fixture with elapsed times `[1,2,4]`, event indicators `[1,1,0]`. | Likelihood estimate rate `2/7`; treating the last 4 as an event gives incorrect `3/7` and must fail. A censored endpoint has no numeric residual. |
| `OR-05-competing-exits` | Two synthetic mutually exclusive exits, A and B, with fixed risk-start, last-observed and cause. Generate one cell where B precludes A and one where both cause-specific clock representations fit the marginal A times. | Preserve both cause incidence and time-to-event; reject a fit that silently discards B or claims a unique cause-specific clock from a non-identifiable marginal. |
| `OR-06-temporal-and-episode-leakage` | Two episodes for one synthetic case across ordered days; an episode crosses a training cutoff and completes later. Put one derived target and one future-known covariate in later rows. | Split by case/episode grouping policy and time blocks before all transforms. Training sees censor-at-cutoff, never later completion; no patient/episode crosses partitions when a stable grouping key exists; future feature rejected. |
| `OR-07-cluster-uncertainty` | Two days with values `[0,0]` and `[10,10]`; compare day-cluster resampling with row-IID bootstrap. | Cluster means have support `{0,5,10}`, probabilities `{.25,.5,.25}`, variance `12.5`; row-IID variance is `6.25`. Label inference unit `day`; a crossed patient/day sensitivity is required only if patient repeats are observed. |
| `OR-08-W1-KS-analytic` | Reference `[0,2]`, simulation `[1,3]`; also identical `[0,2]`, and tied point masses `[0,0]` vs `[1,1]`. | W1=1, KS D=.5; identical gives both zero; separated point masses give both 1. Exact rational result before output conversion. |
| `OR-09-ties-order-and-batches` | Repeat OR-08 with shuffled rows, tie permutations, batch splits and worker completion permutations. | Canonical rows/hashes and metric outputs match exactly under fixed integer/rational accumulation; no tie-order or batch-order effect. |
| `OR-10-missing-censor-failure-counts` | Mix observed event, right-censored, unknown, excluded, unmatched paired case, probe timeout and infeasible prediction. | Counts remain visible under C0.2 definitions; empty/insufficient/invalid/unverified metrics have null values, never zero; failed/infeasible work cannot improve an objective through silent omission. |

The exact fixture inputs, generated-output hashes, and hand calculations should
be checked into the future C1/C4/C5 executable fixture work only when those
owners prepare their implementation packets. This proposal does not fabricate a
runtime pass from paper arithmetic.

## Endpoints and objective construction

Freeze the following **candidate** objective for synthetic recovery experiments
only. Compute each component on training/calibration data and prespecified
validation slices; never tune terms on the locked test set:

- `J_flow = W1 / s_time` for named observed flow durations with matching start/end
  semantics. `s_time` is the training-set reference median absolute deviation
  (MAD) when positive; otherwise use a declared domain scale fixed before fitting.
- `J_shape = KS_D` for the same endpoint and same eligibility window. It remains
  a separate dimensionless shape term, with no p-value by default.
- `J_rate = |p_sim - p_ref| / s_rate` for a named binary/competing endpoint
  (for example, event/censor proportion), where `s_rate` is fixed from training
  data and bounded away from zero by a declared floor.
- `J_coverage` is a typed feasibility gate over missing, censored, excluded,
  unmatched, failed and infeasible counts. It is not a tunable reward for
  dropping difficult rows. A required provenance or denominator failure makes
  the candidate invalid/unverified rather than lowering its score.

For synthetic recovery only, an equal-weight composite
`J_synthetic = (J_flow + J_shape + J_rate)/3` is proposed when all three terms
are defined; candidates are first filtered by `J_coverage`, then ordered by the
composite, then by stable candidate ID for exact ties. This is a test oracle,
not an ED utility function. For a single estimand, report its component without
inventing missing terms. Any actual ED multi-endpoint weights and clinical
acceptance threshold require an explicit intended-use decision and owner signoff;
no evidence in Reports 6/12/30 justifies equal clinical importance.

Never normalize a test metric using test-set values. Fit scales only from the
training split and persist their values/provenance in the study manifest. If MAD
is zero/undefined, use only a prespecified fallback scale; otherwise mark the
term undefined. Report raw units and normalized value side by side. Keep
primitive service fitting separate from aggregate boarding/LOS validation.

## Split and lock protocol

1. Freeze the estimand, eligible events, source mappings, covariate availability,
   unit conversions, candidate families/bounds, objective terms, scales,
   tolerance, seed schedule, and inference method before fitting.
2. Group repeated records by the highest stable dependence key available
   (episode, then pseudonymous patient); do not split one entity across a random
   row partition. Preserve chronology with contiguous whole-day or longer blocks.
3. Use a three-way temporal arrangement: earlier training/calibration block,
   later validation block for prespecified selection, and a final later locked
   test block. The Report 12 `60/20/20` ratio is one provisional planning example,
   not evidence-backed and not mandatory. Select block boundaries based on
   adequate coverage/precision for prespecified strata; if inadequate, report
   `insufficient_data` rather than shrinking the test after seeing outcomes.
4. Censor any in-progress episode at each partition boundary using only
   information available by that boundary. Do not import completion, disposition,
   or covariates learned later into training features.
5. Validation may select only among the already frozen candidates. After any
   model/feature/boundary/weight/tolerance change prompted by locked-test results,
   that test is consumed; a new later holdout is required.
6. Historical exogenous arrivals may be replayed when declared, but downstream
   queues, service starts/completions and outcomes in a predictive holdout remain
   endogenous/free-running. Anchored/clamped outcomes are diagnostics and cannot
   substitute for predictive holdout validation.

If stable patient identity is unavailable, episode grouping and day blocks remain
mandatory, with repeated-patient dependence listed as unresolved. Do not claim
independent-observation confidence intervals from row count alone.

## Tolerance and decision rules

For exact integer/tick semantics, equality is required for IDs, split membership,
counts, event ordering, censor status, candidate enumeration, residual sign and
magnitude, and fixture outputs. No epsilon applies to these contract assertions.

For `W1` and the synthetic composite, retain integer supports and compare exact
rational values in the oracle. Where an implementation emits an IEEE-754 value,
use absolute error no greater than `1e-12 * max(1, declared_scale_in_ticks)`
against the rational oracle for the analytic fixture suite; test scale invariance
by converting ticks exactly before the final output conversion. This is an
implementation conformance tolerance, not a clinically meaningful discrepancy.
A different output representation may use exact equality or a stricter tolerance.
Cross-compiler/backend ranking stability is tested separately: if candidate score
differences are within the declared comparison tolerance, report a tie/ambiguous
ranking rather than silently selecting by unstable float noise.

No universal empirical W1/KS/rate cutoff or 95% predictive coverage threshold is
set here. The correct threshold depends on intended use, endpoint consequences,
data quality and uncertainty. Until those are specified, real-data outcomes may
be labelled descriptive/provisional but cannot pass a calibration adequacy gate.

## Uncertainty and abstention

Separate (a) Monte Carlo variation across replications under fixed inputs and
parameters from (b) input-data/refit uncertainty across supported resamples and
refitted candidates. Report each interval’s method, replication/resample unit,
seed schedule, number of attempts and coverage counts. Common-random-number
candidate comparisons are paired only under the C0.2 shared schedule identity and
a verified compatible seed map.

Use whole-day resampling as the conservative default only when day is observed
and is a defensible independent block. If repeated patient IDs cross days, add a
predeclared patient/day crossed sensitivity method; if cluster IDs are unknown,
state the limitation and do not make row-IID inference claims. Censoring requires
a method justified for the actual censoring mechanism; the first release may
report uncensored-subset distances with explicit coverage warnings but must not
claim censoring correction.

Return an explicit `unidentified`, `insufficient_data`, `unverified`, or
`invalid` state when: a material objective ridge remains; a required endpoint or
provenance mapping is unsupported; split strata lack coverage; event/censor
status is unknown; the needed dependence unit is absent; objective scales cannot
be estimated under the prespecified rule; or failed/infeasible probes exceed a
predeclared eligibility limit. Do not report a point estimate or metric value as
zero in those cases.
