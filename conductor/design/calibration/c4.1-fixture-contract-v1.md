# C4.1 synthetic metric fixture/test contract v1

Owner: Track 21 semantics, Track 12 independent fixtures. Scope is C4.1 test-first
qualification only. C4.2 implementation, C4.3 sidecars and C4.4/C-04 acceptance
remain open. No public Rust API, runtime dependency, scheduler or schema change.
Supersedes the older preparation proposal's missing-API stop for this bounded
fixture-first interface only; it does not authorize inventing a production API.
Kairos workflow permits test-only mocks/interfaces behind reviewed contracts.

## Exact fixture protocol

`conformance/c41/fixtures.json` has `schema_version: "c41.fixtures.v1"`,
`cases` (unique IDs), and `provenance` describing synthetic construction. Each
case has `id`, `family`, `input` and `expected`. Input values/ticks/weights and
counts are decimal or rational strings; nonfinite tokens are `NaN`, `Infinity`,
`-Infinity`. No private/source patient identities. Input declares `unit`,
`scale_ticks` (positive exact string), and `algorithm_version`.
Expected records have `status` (ok/invalid/insufficient_data), `w1` and `ks_d`
(exact rational strings or null), `unit`, `scale_ticks`, `algorithm_version`,
`counts` (string-valued), `precision` (exact_offsets/rejected/not_applicable),
`weighting` (equal/explicit), `warnings` (canonical array), and `p_value: null`.
Family-specific information may be added under `diagnostic` (exact JSON).

Base algorithm `empirical_equal.v1`: stable union supports, aggregate all ties,
normalize each side independently; W1 integrates absolute empirical CDF gap and
KS_D takes its maximum after each whole tie. Integer/rational reference arithmetic
is exact. Optional `weighted_descriptive.v1` normalizes finite nonnegative weights
per side, retains zero-weight observations in counts but not mass, aggregates ties,
and requires positive finite total mass. Weighted KS_D is descriptive only.
No p-values, survival adjustment, row-IID assumptions or fitted acceptance cutoff.

Empty eligible point populations are insufficient_data, not zero. Malformed or
nonfinite values/weights, negative weights, count/weight length mismatch, zero
mass and nonfinite total mass are invalid. Zero distance on observed-only data
must retain censoring/missing/failed/infeasible coverage warnings. Input cohort
counts reconcile as eligible + excluded; eligible reconciles as observed +
right_censored + missing + failed + infeasible. Null points count as missing,
not observed; rejected observations are never silently imputed to zero.

For large ticks, input declares ONE common exact origin, subtracts it in integer
arithmetic for both sides and then verifies exact binary64 representability of
each required offset. Reject precision loss or values outside unsigned u128
before conversion; no independent origins, wrapping or calendar-time metric.
The upper u128 endpoint is valid; one larger is invalid. Rejected precision cases
have null values. `scale_ticks` is fixed per case, never fitted to results.
W1 output tolerance = 1e-12 * max(1, scale_ticks); KS_D tolerance = 1e-12.
This is synthetic implementation conformance tolerance only, not clinical fit.
IDs, counts, statuses, warnings, unit, precision, weighting, p_value, provenance,
and diagnostic grouping metadata require exact equality. Rational fixtures are
exact; output conversion cannot alter event order or integer assertions.

Required families: shift/identical/ties/unequal populations, weighted variants,
zero weights, duration scaling, unsorted/permuted/symmetric inputs, fractional
and signed residual supports, tail W1=180/D=1/5, empty, null/nonfinite/weight
invalids, explicit coverage/censor/missing/failed/infeasible and no-observed data,
large common origin, near-u128 limit, u128 overflow and precision rejection.
Equal-marginal/opposite-dependence uses fixed X={0,1} groups and compares Y;
both marginals are zero but conditional W1=1 in each group. Prespecify group X=2
as empty/insufficient_data, retain eligible counts, and do not infer multivariate
calibration quality from marginal agreement.

## Independent references

`generate_reference.py` uses Python Fraction for authoritative rational support
and separately runs pinned SciPy 1.18.1 / NumPy 2.5.3 W1 and unweighted KS_D.
Pin exact binary wheels and SHA256 in requirements-reference.lock; verify hashes
against official PyPI release metadata before installation. Separate environment,
no Rust/runtime Python dependency. Weighted KS has no claimed SciPy KS analogue;
use independently normalized rational CDF reference. SciPy p-values are discarded.
Generated `reference.json` binds generator, fixtures, wheels and versions; exact
cases and independent floating crosschecks are separate. Reproduction output is
canonical and source-hash bound; generation times belong in execution receipts.

## Native tests and future C4.2 report

`crates/kairo-ecs-calibration/tests/metrics_c41.rs` is test-only. Default tests
validate fixture serialization/coverage, exact expected values and reject mutated
candidate reports. They validate an oracle/comparator, NOT a production metric.
The named `c42_candidate_report` test is explicitly ignored by default because
there is no runtime metric producer. Opt-in execution requires
`C41_CANDIDATE_REPORT` pointing to an actual future C4.2 result. Missing report
is an expected red preparation gate and remains retained, not a metric regression.

Candidate JSON: `schema_version: "c41.candidate.v1"`, `fixture_sha256`,
`provenance` with nonempty producer commit/toolchain/algorithm versions, and
`cases` with exact membership, unique `id` and `result`. Result has expected
fields above, but w1/ks_d are finite JSON numbers or null; reject extra result
fields, nonnull p-values, unknown schema/algorithm/units, changed counts,
missing/extra/duplicate cases, nonfinite output and incorrect precision/warnings.
The comparator must test numeric equality within declared bounds, exact metadata,
null/status coherence and complete case membership. Mock candidate copies are
labeled comparator self-tests; never evidence of a runtime metric implementation.
C4.2 must bind its actual private producer/API before opting in; it may not simply
copy expected fixtures. No ignored existing test, relaxed gate or global allow.
