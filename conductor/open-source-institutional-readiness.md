# Open Source and Institutional Readiness

## Target posture

KairoECS should be acceptable to individual users, research groups, public-sector organizations, and enterprises that need security and governance signals.

## Required trust signals

```text
OpenSSF Scorecard workflow
OpenSSF Best Practices Badge checklist
SECURITY.md
SBOM generation
artifact attestations
checksums
license policy
dependency policy
vulnerability disclosure process
maintainer governance
release signing/verification docs
```

## Institutional adoption checklist

- Clear license.
- Security contact and vulnerability process.
- Dependency update automation.
- Public changelog.
- Compatibility and deprecation policy.
- Supported platform matrix.
- Reproducible examples.
- Citation metadata.
- Release artifacts with checksums and provenance.
- Documentation site with versioned docs.
